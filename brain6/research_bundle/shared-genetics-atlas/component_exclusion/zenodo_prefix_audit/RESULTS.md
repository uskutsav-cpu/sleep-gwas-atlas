# Physical-component GWAS: limited build and source-consistency audit

A bounded check of the first 131,072 compressed bytes of the [Zenodo exhaustion GWAS](https://zenodo.org/records/14011550) provides evidence that **this sampled prefix uses GRCh37 coordinates**. All 20 preselected, non-palindromic chromosome 1 variants had the same rsID, reported position, and allele pair in the 1000 Genomes Phase 3 GRCh37 reference. For 19, treating the reported position as GRCh38 and lifting it to GRCh37 did not yield a matching reference record; the remaining row could not be uniquely lifted and was not used in that comparison. This supports a build interpretation for the checked rows, not a formal declaration of the full file's genome assembly.

Using equal-sized prefixes from the other four component files, 20 of the 20 selected exhaustion variants matched uniquely by chromosome, rsID, position and unordered allele pair in each of the grip-strength, physical-activity and walking-speed prefixes; 19 matched in the weight-loss prefix. The remaining weight-loss variant was not in the **truncated prefix**, which does not establish its absence from the full file. These matches suggest consistent coordinate conventions across the sampled starts of the five files; they do not certify every chromosome or archive.

The exhaustion prefix has columns `CHROM`, `GENPOS`, `ID`, `ALLELE0`, `ALLELE1`, `A1FREQ`, `BETA`, `SE`, `CHISQ`, and `LOG10P`. Standard [Regenie documentation](https://rgcgithub.github.io/regenie/options/) describes its output effects in terms of allele 1, but the downloaded files have been processed and lack the original commands and complete metadata. The observed labels alone do not establish their exact effect convention, binary/quantitative model, ancestry, covariates, missingness or participant overlap. The record's filenames mention MAF and imputation filters, but a filename does not document all QC. The phenotype construction and source-study lineage are still unconfirmed. **Do not use these prefixes as component GWAS or claim a sleep-excluded frailty result.**

This was an observational source check, not a cross-trait association test. The [protocol](PROTOCOL.md), [sampled rows](selected_rows.tsv), [reference matches](build_matches.tsv), [four-component comparison](component_prefix_matches.tsv), scripts and [receipts](reference_receipt.json) document selection and results. The five `.bin` files contain only the first 131,072 compressed bytes each and are intentionally **not complete gzip archives**; their prefix hashes are recorded. The [full exhaustion archive](../zenodo_full_exhaustion_audit/RESULTS.md) was subsequently streamed and its publisher MD5 verified; the other four full-archive MD5 values have not been verified. The GRCh37 reference was queried through the UCSC-hosted indexed VCF without a whole-file hash. The hg38-to-hg19 chain is an external dependency recorded by SHA-256. A range check confirmed the server supports HTTP 206, but source bytes may change in future.

The next substantive step requires the file creator's original model/allele/ancestry documentation or independent source validation, then complete-file checksum verification and appropriate access, QC, ancestry-matched LD, phenotype and overlap review. Even valid component GWAS would analyze separate traits; they would not reconstruct a matched same-person FFS-minus-exhaustion GWAS.
