# Exhaustion GWAS: whole-file checksum and GRCh37 reference audit

The complete [Zenodo exhaustion summary file](https://zenodo.org/records/14011550) was streamed without retaining the full archive. Its **241,965,013 compressed bytes** passed gzip completion and matched the publisher's MD5 (`d46eb916b59abfea983d2e03d9ee7b1c`). The source SHA-256, reference hash, code and counts are in the [receipt](receipt.json); [the protocol](PROTOCOL.md) was written before inspecting the result.

The file contains **8,380,907 rows**. Of these, 1,020,541 have an rsID in the existing GRCh37 HapMap reference map. All 1,020,541 of those rows matched the map's chromosome and position; 1,019,668 also matched its unordered allele pair, while **873** had a different allele pair. The other 7,360,366 source rows did not have an ID in this particular HapMap map; they are outside this comparison, not mismatches or evidence of no effect. At least 861 reference-matched rsIDs occurred more than once in the source, so these are **row counts**, not independent variants or loci. A [subsequent duplicate audit](../zenodo_duplicate_audit/RESULTS.md) found that most mismatch rows have a same-ID source row with the reference allele pair; 11 do not. All require allele-specific review rather than rsID-only matching. The [chromosome-level table](by_chromosome.tsv) shows matches across autosomes 1–22. Numeric-field validation found no invalid rows under the stated simple range/finite checks, which is not a validation of the GWAS model.

Together with the earlier independent [1000 Genomes prefix check](../zenodo_prefix_audit/RESULTS.md), the whole-file ID/coordinate agreement provides stronger evidence that the exhaustion file uses GRCh37 positions. It does not validate positions for source variants outside the HapMap map, prove the effect allele or scale, or establish phenotype coding, ancestry, participant overlap, per-variant sample size, covariates or imputation QC. The [four other component archives](../zenodo_full_physical_audit/RESULTS.md) were subsequently checksum-verified and compared to the same reference, with similar remaining limitations. The reference map itself is a filtered project resource, not an independent whole-genome truth set. Allele-pair agreement is unordered and cannot establish effect direction. No component–sleep genetic association was calculated, and the file is not an FFS-minus-exhaustion GWAS.

[Audit code](audit.py) re-streams the source and requires the external HapMap map path recorded there. The script verifies the published MD5 and gzip completion before writing its output; it records the actual reference SHA-256 rather than assuming a remote VCF version. Further analysis remains held pending source-level model and phenotype documentation, ancestry-appropriate LD, duplicate/multiallelic resolution and overlap review.

A [published-context check](../zenodo_published_context/RESULTS.md) found the depositor’s later article and its observational exhaustion definition, but could not establish that the separate component GWAS used that exact definition or model.
