# Full original general-factor verification using ordered HTTP ranges

After the original full-stream attempt timed out, retrieve the GRCh37 general-factor file in fixed 2 MiB HTTP byte ranges with bounded parallelism, without writing the complete file to disk. Require HTTP 206, exact expected byte length for every range, and `If-Match` with the initial strong ETag. Retry a failed range from its original boundaries into a fresh in-memory buffer; never append a retried partial response. Hash and parse successful ranges strictly in increasing byte order, carrying incomplete lines over range boundaries. Validate the header, every row width, final newline and total bytes. Accept the extracted 87-variant crosswalk only if the completed stream's MD5 equals the original publisher declaration. Retain SHA-256, ETag, range count, extraction statuses, selection hash, and code. Compare to the separately harmonized GRCh38 lookup after documented liftover and allele alignment; an unmatched original row or harmonized row is not a negative association. Do not substitute these reused factor data for independent replication.
