# Original-release positive-record crosscheck by byte range

While the full source streams remain pending, use short HTTP Range reads from the original GRCh37 general-factor file for four prior anchors already returned in the harmonized lookup. Binary-search sampled coordinates only as a lookup heuristic: metadata say the original file is not guaranteed sorted, so a failure to find a target cannot establish absence. A positive result must contain exactly the requested rsID, position and unordered allele pair, be bounded by complete newline-delimited source rows, and agree with expected source header fields. Save the exact returned source row, byte ranges, source URL and file size; compare beta/SE/p and Q with the independently queried harmonized record, accounting explicitly for effect-allele orientation. HTTP partial reads do not verify the complete publisher MD5. Check source HTTP ETag/last-modified and MD5 metadata at read time, and do not label the indexed and original releases as independent GWAS or replication. A successful crosscheck verifies only the returned target record, not whole-file integrity or presence of all neighboring variants.
