# FFS output integrity incident

On 27 October 2026 both original PLACO+ workers reported successful exits. The completed-scan audit stopped on an invalid status in the FFS output, and independent `gzip -t` and Python gzip reads found a CRC mismatch in `FFS_screen.tsv.gz`. Exit code 0 was therefore insufficient to establish output validity. The affected file has been preserved in its original location and must not be used to report candidates. The root cause of its corruption is unknown; the contemporaneous low-space condition is a concern but is not proven to have caused it. A checksum manifest can attest to preservation of those bytes, not that a gzip file is valid.

The FI gzip passed `gzip -t` and an FI-only version of the completed audit verified all 1,138,262 aligned rows and all 2,191 stored controls. Its threshold-crossing candidate file is diagnostic and keeps the originally defined two-pair denominator (2,276,524 tests); controls do not establish stringent-level type-I calibration.

A full FFS rerun was started in two contiguous chunks, 1–569131 and 569132–1138262, using the pinned source, same inputs and parameters. The chunk executor first passed a 100-row smoke test: its output was gzip-valid and matched the first 100 rows of the damaged original exactly. This checks executor consistency at those rows, not integrity of the rest of the old output. The two full chunks write to `/Volumes/Extreme SSD/brain6-placo-ffs-rerun-20261027`; the original file remains untouched. Completion, gzip checks, the complete row/control audit and source-statistic sensitivity are all still required before reporting full FFS results. Follow [PROTOCOL.md](PROTOCOL.md) for recovery.

A subsequent read-only structural inspection (`inspect_corruption.py`, `corruption_diagnostic.json`) encountered the first malformed output row at the 1,049,524th streamed row, followed by many key, status and numeric mismatches before Python's gzip reader raised a CRC error. Once a broken row changes record boundaries, subsequent comparisons can become misaligned, so the reported mismatch counts must not be interpreted as counts of independently damaged variants. This forensic pass cannot establish that earlier or apparently well-formed PLACO values are correct, identify the cause, or justify using a partial prefix as a completed scan. No bytes were repaired or deleted.

Recovery update: both replacement chunks completed successfully; both chunks and the newly combined output passed gzip checks, and each chunk contained exactly 569,131 rows. The combined file passed the full 1,138,262-row alignment audit and all 2,191 controls. Candidate source and statistic sensitivity checks are summarized in the [completed diagnostic](../completed_audit/RESULTS.md). The damaged original remains preserved and unused.
