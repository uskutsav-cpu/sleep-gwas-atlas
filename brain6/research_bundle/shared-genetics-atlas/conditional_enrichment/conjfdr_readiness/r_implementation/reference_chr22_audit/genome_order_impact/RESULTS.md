# Genome-wide chromosome-block impact of the original ordering

Applying the inspected package's documented ordering operations to the published reference variant list and the existing shared-support insomnia SNP list shows a **material ordering defect for these inputs**. After rsID intersection and the package's default reference MAF >0.005 filter, 1,128,469 variants remained. In the original rank-as-index order, **1,069,329 rows (94.76%)** would lie in a chromosome pruning block belonging to a different chromosome from the row's reference chromosome. Only 59,140 rows would be in the matching chromosome block.

This calculates the chromosome blocks that the unmodified code would construct from per-chromosome counts; it does **not** run the package's full initialization or pruning on the study data, estimate actual FDR distortion, or evaluate any real association. The calculation uses only variant IDs, reference chromosomes, positions and reference MAF. The existing FI and FFS files were previously audited to have the same SNP ordering as the insomnia common-support file; this check does not re-establish their allele/build alignment or imply they are valid inputs for the package. Variant exclusions or other settings would change the exact count.

The documented code first sorts by rsID, computes each row's genomic rank, uses that rank vector as row indices, and later fills pruning indices in contiguous chromosome-sized blocks. A rank vector is not generally a sorting permutation. The [calculation](audit.R) independently checks the `data.table::frank` result against base R inverse-order ranks. The [per-block counts](chromosome_counts.tsv), [cross-chromosome count table](cross_chromosome_counts.tsv), and [log](run.log) make the mismatch inspectable. The sleep SNP file and reference member hashes are preserved in the [chromosome 22 audit](../study_support/RESULTS.md).

The [local correction](../../synthetic_order_check/patch_check/RESULTS.md) passes bounded synthetic alignment tests, but the real-data result above does not validate the patched full pipeline. The additional empty-neighbor issue, sample-overlap correction, reference and allele compatibility, memory, full-method behavior and statistical calibration remain to be resolved. No real association statistics were used in this check, no conjunctional FDR run has been performed, and no LAVA QC gate has been repaired.
