# Published reference: chromosome 22 sparse-matrix audit

The empty-column issue previously found with synthetic data is relevant to the published `cfdr.pleio` reference. The [Zenodo reference archive](https://zenodo.org/records/5750318) chromosome 22 matrix has **135,564 columns**, of which **121 have no stored neighbors**. The matrix is an `ngCMatrix`, is symmetric by R's matrix check, and has a zero diagonal. Column names are present; row names are absent, so this inspection alone does not independently verify row-to-column variant identity.

For a fixed sample of 120 columns, including 20 selected empty columns and 100 randomly selected columns, the original `which_col` disagreed with ordinary matrix extraction in **20 of 120** cases—all 20 selected empty columns. The locally patched function agreed in **120 of 120**. This checks retrieval of stored neighbors for that sample; it is not a test of the full pruning or FDR procedure, and does not measure the impact on any GWAS analysis. A subsequent [study-support restriction](study_support/RESULTS.md) found 39 empty columns, including 38 that became empty only after restriction.

Two individual archive members, the variant list and chromosome 22 matrix, were retrieved directly to the SSD via HTTP ranges. Both completed full member reads with ZIP CRC checks; the [receipt](retrieval_receipt.json) records sizes and SHA-256 hashes. The entire 3 GB archive and its publisher MD5 were not verified. The [inspection code](check.R), [log](run.log) and [retrieval code](retrieve.py) document the check. No real GWAS were passed to the R implementation.

This evidence strengthens the need for the [local empty-column correction](../synthetic_order_check/patch_check/isolated_variants/RESULTS.md), but does not validate it for every matrix class or the complete reference. Ordering, variant alignment, study overlap, complex LD graphs, full-method calibration, independent validation and computational requirements remain open. The existing corrected copy has not been approved as a discovery pipeline.

A [genome-wide chromosome-block audit](genome_order_impact/RESULTS.md) finds that the uncorrected order would place 94.76% of matched, MAF-filtered rows under the wrong chromosome pruning block for this SNP list. This is a reconstruction of indexing, not a full FDR run or a measured impact on discoveries.
