# Chromosome 22 reference after sleep–frailty support restriction

Intersecting the published chromosome 22 reference with the existing shared-support registry-insomnia SNP list by rsID, then applying the R package's default reference MAF >0.005 filter, retained **16,444 variants**. The earlier input audit reports identical SNP order in the FI and FFS companion files. This is an rsID and MAF availability check, not a new allele/build harmonization or an FDR analysis.

On the corresponding reference submatrix, **39 variants (0.237%)** had no retained neighbors. Only one was already an empty column in the original chromosome 22 matrix; the other 38 became empty after this study-support restriction. Thus the original empty-column lookup defect can matter after filtering even for variants that originally had neighbors. No analysis was run with the defective lookup, and this does not establish the effect on FDR estimates or results on other chromosomes.

The chromosome 22 reference variant table and matrix column IDs agree exactly in their original order (135,564 unique IDs). Matrix row names are absent; identity of rows and columns is a convention of the source and is not independently proven by this comparison. The original rank-as-index operation produces a different within-chromosome sequence from genomic sorting at **16,442 of 16,444** retained positions. This demonstrates that the operation does not implement the documented ordering. It does **not** by itself prove incorrect pruning in a one-chromosome fit: both the trait rows and corresponding chromosome matrix are reordered together there. The previously demonstrated multi-chromosome interleaving is the distinct risk that needs correction and validation.
