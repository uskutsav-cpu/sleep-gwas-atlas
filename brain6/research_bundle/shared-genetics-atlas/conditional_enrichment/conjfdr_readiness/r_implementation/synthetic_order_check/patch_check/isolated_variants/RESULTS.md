# Synthetic isolated-variant pruning check

A second issue was confirmed in the inspected `cfdr.pleio` version: for a general sparse matrix with an empty first column, the unmodified `which_col` returns a row from another column instead of an empty vector. In the three-variant synthetic example, it returns `3` for isolated variant 1; the expected result is no neighbors. The [unmodified reproducer](unpatched_check.R) and [log](unpatched.log) show this case. It could cause an isolated variant to suppress an unrelated variant during pruning; the impact on any GWAS analysis has not been established. A later [chromosome 22 reference check](../../../reference_chr22_audit/RESULTS.md) finds 121 empty columns and reproduces the mismatch on a sampled subset.

A second, separate local copy includes the earlier genomic-order patch and an [empty-column patch](empty_column.patch), returning `integer(0)` for an empty sparse-matrix column. With a **general** compressed sparse matrix (rather than a symmetric-storage matrix), a synthetic test of 66 variants across 22 chromosomes retained every isolated variant and exactly one of each linked pair in all ten fixed-seed pruning iterations. It also checked alignment across three input permutations and the exclusion of one trait variant absent from the reference. The [test code](check.R) and [log](run.log) preserve the check. Neither local patch modifies the original package copy or an upstream release.

The earlier 44-variant test used a symmetric-storage test matrix, so its pruning result should not be taken as a complete check of general sparse-matrix neighbor extraction. The new general-matrix test is stronger for the cases it covers, but neither establishes correctness for the actual reference's storage format, diagonal conventions, duplicate/ambiguous variants, complex LD graphs, full FDR computation, sample-overlap handling or statistical calibration. No real GWAS were analyzed. The method remains unqualified for a discovery scan.
