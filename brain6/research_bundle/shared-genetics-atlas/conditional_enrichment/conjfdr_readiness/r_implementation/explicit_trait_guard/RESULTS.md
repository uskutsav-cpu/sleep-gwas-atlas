# Explicit trait-argument guard: reproduced software defect

In the inspected [cfdr.pleio source](https://github.com/alexploner/cfdr.pleio/blob/76d5085e6d3f3ca9576d5d7564d2acf11bcfd021/R/cfdr_pleio.R), `calculate_cond_fdr` accepts two trait indices, each limited to 1 or 2. If both are supplied, its guard requires `cond_trait + fdr_trait != 3`. This rejects both different-trait pairs `(1, 2)` and `(2, 1)` while letting equal-trait pairs past that guard. The documented one-argument route derives the other trait as `3 - trait` and takes a separate branch.

The [test](test.R) used an empty object with the locally ordering/empty-column patched package and checked all four explicit pairs. The two different-trait calls stopped at the guard; the equal-trait calls advanced past it but stopped later because the object had no data. The [recorded output](results.tsv) therefore **does not show** that equal-trait analyses successfully complete, nor does it assess the numerical output of any valid call. The same guard text appears in the original inspected source. Package version was 0.0.0.9100, original checkout commit `76d5085e6d3f3ca9576d5d7564d2acf11bcfd021`; SHA-256 for the original and patched source files were respectively `2c4c0c3444902b915cb3c1821333a1f1635f2d979520f0cc268849b8d547e289` and `58316845b29f2a01266e303ccf992c34bc5c8ae9316b0e08edbb1d99fbb838cf`.

The prior synthetic calibration scripts specified only `fdr_trait`, so they did not use this explicit two-argument branch. This input defect cannot explain their false crossings. We did not change the installed package; a future fix needs its own regression tests, upstream review and full statistical validation. The separate smoothing-related calibration concern and absent sample-overlap correction remain unresolved. No real-data conjFDR result is justified by this finding.
