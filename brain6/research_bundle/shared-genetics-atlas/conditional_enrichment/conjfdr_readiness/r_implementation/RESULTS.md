# An R alternative for conjunctional FDR

The [cfdr.pleio repository](https://github.com/alexploner/cfdr.pleio) implements conditional and conjunctional FDR in R, based on a 2021 fork of the MATLAB pleioFDR code. The inspected source is commit `76d5085e6d3f3ca9576d5d7564d2acf11bcfd021`, version `0.0.0.9100`. This provides a potential route without MATLAB; it is **not** evidence that the present study can be analyzed validly or that the R and current MATLAB versions produce identical results.

The version's `init_data` documentation and source explicitly say `correct_SO=TRUE` is not implemented and stops with an error; its default is `FALSE`. This matters because the FI/FFS and insomnia inputs can share participants, and the FI itself includes sleep items. The package's separate `correct_GC` option concerns genomic correction and is not a validated substitute for sample-overlap correction. An independently justified solution for overlap, including whether it can be used with this implementation, is needed before interpreting FDR estimates. The source also warns that an existing, nonempty `local_refdat_path` is overwritten. Future use must create a new dedicated output directory and preserve existing files.

The documented [Zenodo reference](https://zenodo.org/records/5750318) `genref.zip` has 3,012,662,640 bytes and published MD5 `4af12e08eb4fca0e60c4eaa2d783e50c`. Its remote ZIP directory lists 23 stored entries totaling 3,012,658,882 bytes, so retaining the ZIP and its extracted entries would require about 6.03 GB before project-specific data and working space. A range-only directory inspection does not verify the full archive or its checksum. At this check the external SSD reports 4.8 GiB free, the mounted work image 288 MiB, and the computer has 8 GiB RAM. Memory needs of this R implementation for the full dataset have not been measured. The user requested SSD use and no unapproved deletion; the reference has not been downloaded or extracted.

The R runtime initially lacked `binom` and `interp`; these dependencies and the inspected package were subsequently installed on the SSD work image. Its full vignette example needs the reference and example GWAS data. A [six-variant synthetic initialization test](synthetic_order_check/RESULTS.md) found a possible trait/reference ordering mismatch in this version. A later [synthetic end-to-end check](synthetic_full_pipeline/RESULTS.md) completed both directions on an artificial no-LD reference. No full-vignette example or real-data conjunctional FDR scan has been run here. A reliable analysis still needs precise dense GWAS inputs, ancestry-appropriate LD, sample-overlap handling, reference integrity, adequate storage and memory, a reproducible example, frozen parameters, and calibration and negative controls. The existing max-p screen and enrichment plots are not substitutes for this method.

The source was cloned read-only in intent to `/Volumes/Brain6Work/cfdr-pleio-source` for inspection; no existing analysis directory was passed to its overwrite-capable initializer. SSD availability is a snapshot, not guaranteed usable space. See the [previous readiness audit](../RESULTS.md) and the [data preparation and model limitations](../../RESULTS.md).

A [separate local ordering patch](synthetic_order_check/patch_check/RESULTS.md) passed a synthetic 22-chromosome alignment and pruning test. It has not been validated on real reference data or the full FDR method and does not implement sample-overlap correction.

A further [isolated-variant pruning test](synthetic_order_check/patch_check/isolated_variants/RESULTS.md) exposed and locally patched a second issue in empty sparse-matrix columns. The full method and actual reference remain unvalidated.

A [published chromosome 22 reference audit](reference_chr22_audit/RESULTS.md) finds empty sparse columns in the real reference and confirms the lookup defect in a sampled subset. The patched lookup matches ordinary extraction for those sampled columns, not a full-method validation.

A [small one-trait-only, correlated-error simulation](synthetic_overlap_stress/RESULTS.md) completed without threshold crossings in 10 paired replicates per scenario. Its limited size and no-LD model do not establish calibration or resolve sample overlap.

A subsequent [synthetic LD and overlap stress test](synthetic_ld_overlap/RESULTS.md) produced false conjunction threshold crossings in 6/10 uncorrelated and 7/10 correlated-error runs. This stronger diagnostic argues against interpreting real-data results from the present patched configuration without further investigation; it does not establish the cause or generalize to other implementations.

An [explicit trait-argument check](explicit_trait_guard/RESULTS.md) found a separate reversed guard in the inspected source: valid different-trait pairs are rejected when both arguments are supplied. The synthetic runs used the one-argument branch, so this finding does not explain their calibration failures.
