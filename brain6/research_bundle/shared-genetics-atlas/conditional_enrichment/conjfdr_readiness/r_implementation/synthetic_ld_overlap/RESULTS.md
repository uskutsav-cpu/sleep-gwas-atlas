# Synthetic LD and sample-correlation stress: conjunction-FDR is not ready

The locally patched `cfdr.pleio` implementation produced false threshold crossings in a simple simulation where **every marker is null for trait 2**, so every conjunction null is true. Among ten independently seeded datasets, at least one simulated SNP had conjunction FDR ≤0.05 in **6/10 runs** with zero study-error correlation and **7/10** with correlation 0.3. In this global-conjunction-null setting the false discovery proportion is 1 in a run with any crossing and 0 otherwise, making the observed run fractions estimates of FDR for these exact artificial scenarios. Ten runs give substantial uncertainty; illustrative exact 95% binomial intervals are about [0.26, 0.88] and [0.35, 0.93], respectively.

Each simulated dataset contains 44,000 markers in 4,400 independent blocks of ten, with within-block error correlation 0.5 and a correctly matched clique pruning graph. Five percent of blocks carry a fixed association only for trait 1. The pruning check retained exactly one marker per block in each of five pruning iterations in every run. All output conjunction values were finite and within [0,1]. These results raise a serious calibration concern for this patched implementation and configuration under the stipulated model, including when study errors are uncorrelated. They do not establish why it occurs, whether the original MATLAB method behaves similarly, or the error rate of the real project data. The paired correlation settings share simulated errors; their difference is not evidence that overlap caused the findings.

The independent [warning recheck](warning_recheck.R) reproduced the first zero-correlation run's one crossing and its minimum conjunction value. Its [log](warning_recheck.log) contains ten R warnings about discarded row names in a confidence-interval data-frame operation; we have not established whether these warnings affect numerical results. The original run reported at least 50 warnings but did not preserve their individual texts. The recheck does not establish warning identity across all original runs.

This is a post-hoc software stress test of an artificial LD model, one signal size and one null architecture, with only ten runs per scenario. It is not a genome-wide human-data scan, a clinical result, or a PLACO/LAVA validation. The synthetic reference, seeds, paired inputs, default genomic correction and five pruning iterations are specified in the [pre-run protocol](PROTOCOL.md). [Code](run.R), [all run summaries](runs.tsv), [verification](verification.json), and [verification code](verify.py) record results and hashes; the reference graph remains on the SSD. Further source-code review, independent implementation comparison, broader simulated architectures and an overlap-correction method are needed before real-data conjunction-FDR findings can be interpreted.

A [single-dataset settings sensitivity](method_sensitivity/RESULTS.md) reproduced the first false crossing and found it absent when smoothing was disabled. This is a diagnostic clue, not proof of an implementation error or of unsmoothed calibration.

A separate [500-seed negative-control simulation](maxp_null_calibration/RESULTS.md) had no crossings for max-p with Bonferroni, BY or BH in either tested correlation setting. It examines a different joint-association procedure, not calibration of the conjunction-FDR implementation.

A [strong one-trait-only boundary stress](maxp_boundary_null/RESULTS.md) separately evaluates the same max-p corrections in 1,000 new datasets per setting. Its simple block model and artificial effects do not establish real-data error rates.
