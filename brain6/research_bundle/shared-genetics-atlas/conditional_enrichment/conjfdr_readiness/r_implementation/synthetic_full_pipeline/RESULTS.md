# Synthetic end-to-end conjunctional FDR software check

The local R package copy with the [ordering and empty-column patches](../synthetic_order_check/patch_check/isolated_variants/RESULTS.md) completed a synthetic run in both directions, including initialization, pruning, smoothing and conjunction calculation. The test used 44,000 simulated variants across 22 chromosomes, independently generated Gaussian statistics for the two traits, and an artificial reference with no LD edges. All three pruning iterations therefore retained the same complete variant set.

All returned conditional values were finite and within [0,1], and the conjunction values equaled the maximum of the two conditional values. Swapping trait labels and shuffling input order gave the same conjunction values and exchanged the directional values within numerical tolerance. In this **single synthetic draw**, no conjunction values were at or below 0.05. This count is a software observation, not an estimate of a false-discovery rate or power. The package emitted row-name-discarding warnings from its binomial-interval calculations; the [full run log](run.log) retains them.

The [reproducer](test.R) records seeds, package libraries, parameters and assertions. The run used a new dedicated SSD work directory and no real GWAS or AlphaGenome data. It does not test realistic LD, shared participants, true associations, the published reference, missing/ambiguous alleles, method equivalence to MATLAB, or reproducibility across multiple simulated datasets. It therefore cannot validate statistical calibration, quantify resource needs for a full run, or establish discovery control. The package's sample-overlap correction remains unimplemented; real-data conjFDR has not been run.
