# Three-trait HyPrColoc readiness: not run

The separate pairwise chromosome 5 results do not answer whether expression, insomnia and ADHD share one variant. [HyPrColoc](https://www.nature.com/articles/s41467-020-20885-8) is a published multi-trait method that could address a **model-conditional version** of that question. Its main model assumes at most one causal variant per trait in the region and adequate coverage of the causal variant; for dependent studies it also requires assumptions about shared LD and sample correlations. It does not by itself establish a causal gene, resolve multiple signals, repair LAVA QC, or supply independent replication.

The existing 1,633-variant intersection contains aligned beta and SE for GTEx testis RP11-6N13.1 expression, Brain6 insomnia and Brain6 ADHD. GTEx testis is not brain, the regional selection is post hoc, the underlying cohort overlap and source-specific allele frequencies are not fully established, and the 1-Mb window and common variant support may omit relevant variants. A first exploratory run could explicitly treat trait statistics as independent and test prior sensitivity, but should not claim that actual overlapping studies are independent. A correlated-traits fit would additionally need defensible trait correlations, participant overlap and appropriate LD; arbitrary values cannot validate it. A multi-signal, study-matched analysis remains a separate requirement.

The official [HyPrColoc source](https://github.com/jrs95/hyprcoloc) was inspected at commit `0348bbdd977be731d82e4efda115a9bed63cd44f` (package 0.0.2). The method documentation states that the correlated-studies analysis requires a trait-correlation matrix, LD matrix and sample-overlap matrix. Its code exposes independent-trait mode, outcome types, priors and branch-and-bound thresholds; these settings must be recorded before interpreting a result.

**No HyPrColoc fit was completed.** The dependencies were initially installed on the external drive, but compilation failed when tools encountered spaces in the temporary path and filesystem metadata files. A subsequent installation on the system volume was stopped when free space fell to approximately 164 MiB. A 2-GiB sparse APFS image was created on the external drive to provide a space-free path, but even creating its first directories failed with “No space left on device”; the external filesystem reported no free file entries despite reporting byte capacity. Neither failed installation is evidence about colocalization. No existing user files were deleted. The generated source, installation logs and partial libraries remain in this task's `work/` folder and on the external volume; they are not scientific outputs.

To proceed, provide enough usable system space for a source build, or an external filesystem with available file entries and a working writable volume; verify dependency versions and the pinned package commit, run the package's documented example, then freeze the exact analysis settings and execute independent-trait and sensitivity scenarios. Inspect model output and validate assumptions before adding any result to the atlas. The [existing common-support report](../common_support/RESULTS.md) remains the completed evidence.
