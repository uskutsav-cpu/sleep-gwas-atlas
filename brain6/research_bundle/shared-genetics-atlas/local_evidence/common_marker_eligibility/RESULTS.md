# Common-marker inputs do not by themselves resolve local-analysis eligibility

The new 991,707-marker clinical-insomnia common-support file shares **586 rsIDs** with the **2,741** internal markers saved for the archived insomnia–FI LAVA replay of locus 464 (21.4% of the replay's rsIDs). Both input files matched their earlier recorded SHA-256 values, and the common-support gzip stream was read completely. The intersection is by **rsID only**; it does not verify matching positions, alleles, LD availability or usable variants for a new local fit. It is not a predetermined sufficiency threshold and does not prove that a smaller marker set would fail or pass any method.

The new file was constructed for genome-wide LDSC and differs substantially in source and selection from the original replay. A prior [controlled support diagnostic](../song_lava_receipt/cross_trait/marker_overlap/replay/restricted_support/RESULTS.md) already showed that the original locus's univariate FI variance is sensitive to marker support. Together, these observations do not explain the original failure, validate the new subset or establish a local genetic correlation. The reference LD, participant overlap, effective sample sizes, dense coverage, family-wide calibration and statistical review still need to meet the [new-local eligibility record](../../evidence/NEW_LOCAL_ANALYSIS_PROTOCOL.md). The original family remains failed and **no new local result was run or promoted**.

The [protocol](PROTOCOL.md), [audit code](audit.py), and [receipt](receipt.json) retain the name-only intersection and hashes. This is a targeted feasibility check of one previously selected locus, not a genome-wide evaluation or evidence for or against a shared causal variant.
