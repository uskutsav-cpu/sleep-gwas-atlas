# Public long-sleep source evidence, 2026-09-27

Scope: source discovery and admission evidence only. No association, LAVA, candidate-region, or protected-slot result was run or changed. The locked phenotype is **self-reported ≥9 h versus 7–8 h**, European-ancestry UK Biobank, 34,184 cases and 305,742 controls in [Dashti et al. 2019](https://www.nature.com/articles/s41467-019-08917-4). The frozen source gate requires an auditable analyzed-sample-size and effect-model interpretation for the *released* full-genome statistics; a new phenotype is a new analysis, not a repair of the locked file.

## Current admissibility

**No newly located public source passes.** The exact Dashti file is present and rehashed, but its row-level analyzed N and exact output/model transformation are unverified; no alternate source reviewed here supplies a complete same-phenotype, independently auditable replacement. The 2025 analysis is a concrete lead for acquisition, not a dataset already in hand. The [existing narrow source request](../../lava_longsleep_source_rescue_v1/LONG_SLEEP_DATA_REQUEST.md) remains the immediate unblock for the exact release: a variant-keyed analyzed N/NMISS (or a source-specific proof of fixed analyzed N), plus the export/model statement and the relation to logistic versus linear mixed-model statistics. Do not run or promote on this ledger alone.

The preceding decisions do not claim that no such data exist anywhere; they report what the cited primary public materials and currently mounted, hashed source establish. No new large files were downloaded.

## Exact release model: strong class evidence, limited file provenance

[Dashti et al., Methods, p. 9](https://research-information.bris.ac.uk/ws/files/187399081/s41467_019_08917_4.pdf) report a primary BOLT-LMM additive *linear mixed-model* analysis in related European-ancestry UK Biobank participants, adjusting for age, sex, ten ancestry PCs, array, and genetic relatedness. They report maximum SNP missingness of 10% and sample missingness of 40%. Their **separate odds ratios** came from PLINK logistic regression in unrelated white British participants, with hard-call genotypes. The paper's long-sleep contrast is ≥9 h against 7–8 h, with 34,184 cases and 305,742 controls; these counts describe the study cohort, not an exported per-variant field. A [2019 paper coauthored by this group, Methods](https://www.nature.com/articles/s41467-019-11456-7) explicitly describes public genome-wide long-sleep summary statistics as using BOLT-LMM and cites Dashti. Together with the [original release README](../../lava_confirmatory_source_triage_v1/source_docs/Saxena_fullUKBB_Longsleep_summary_stats_README) and the pre-pilot [source-only SE audit](../../lava_confirmatory_source_triage_v1/longsleep_original_model_20260927.md), this makes BOLT-LMM the **high-confidence release analysis class**. It does not identify the exact output switch, calibration, export, or any subsequent beta/SE conversion for each row. The separate PLINK logistic odds ratios cannot be substituted for the genome-wide release. No association result or pilot arm was used to choose this class.

The [contemporary BOLT-LMM v2.3.1 author manual, §§5.2–5.5 and 10](https://alkesgroup.broadinstitute.org/BOLT-LMM/downloads/old/BOLT-LMM_v2.3.1_manual.pdf) states that BOLT treats binary case-control responses as quantitative in a linear mixed model; a log-odds conversion is a separate approximation. BOLT excludes missing phenotypes and, by default, missing covariates; PLINK genotype missing calls are replaced with SNP averages, while imputed dosages should generally be complete. It also documents SNP/sample missingness filters and says standard BOLT association output contains SNP missingness. These are software semantics, **not** a Dashti run log. They allow a potentially fixed imputed-data cohort, but do not prove that each released variant used precisely 339,926 participants, or that no source-specific removal or postprocessing occurred.

## Can public fields reconstruct variant N?

**No: exact analyzed `N_i` is not identifiable from the released ten columns.** There is no N or missingness field. `INFO` is an imputation-quality measure, not the fraction of people analyzed. `P` largely reflects the test statistic determined by beta and SE; it is not an independent sample-count observation. An inverse-SE estimate would require the unreported residual binary-response variance after covariate/mixed-model adjustment, residualized dosage variance, calibration and relatedness details, as well as missingness. Multiple values of `N_i` with different nuisance quantities can yield the same beta/SE/P. The published cohort total and the stable source-only SE ratios support a **diagnostic approximation**, but cannot recover an integer row-level N or prove it is constant. This is an identifiability limit of these public fields, not a claim that N actually varied.

A source-specific BOLT run/export receipt identifying the included phenotype–covariate–genotype intersection and per-variant missingness, an author-supplied variant-keyed N/NMISS sidecar, or a source-specific documented proof of an effectively fixed analyzed cohort after QC could resolve that uncertainty. Any fixed-N route must also define its missingness exclusion/sensitivity rule and give a source/method-supported mapping from BOLT's binary-response linear mixed-model statistic to LAVA's `STAT`, `N`, and case fraction.

## LAVA precedent versus frozen admission

The [original LAVA methods paper, Methods p. 10](https://research.vu.nl/ws/files/155730906/An_integrated_framework_for_local_genetic_correlation_analysis.pdf) expressly permits **overall N as a proxy when per-SNP N is absent** in its continuous-phenotype Z-to-correlation construction. Its binary-phenotype method, on the same page, reconstructs marginal *logistic* effects from Z and SNP case/control counts before fitting a local logistic model. The [pinned LAVA 0.1.5 implementation](../../lava_confirmatory_protocol_v1/source_docs/LAVA_binary_processing_e729a245.R) likewise uses `N × case.prop` to create case counts for its binary path. Thus the LAVA precedent makes an overall-N continuous-path calculation possible; it does **not** establish that the Dashti released N is exactly constant or validate the binary LAVA path for BOLT's linear-model Z. Nor does it validate treating a binary-response BOLT scan as a continuous phenotype for confirmatory inference.

The pre-existing [sample-size and overlap protocol v1](../../lava_confirmatory_protocol_v1/sample_size_and_overlap_protocol.md) requires source evidence before assigning study-wide counts to every SNP, a source-supported model mapping, and rejection of unresolved critical N/binary-model semantics. The prospective [long-sleep diagnostic addendum](../../lava_confirmatory_protocol_v1/longsleep_linear_model_pilot_addendum_20260927.md) explicitly allowed overall `N=339926` only as a diagnostic proxy; it froze the linear arm as primary, binary as sensitivity, and a minimum 10-percentage-point (≥9/88 net loci) gain before considering a larger screen. **Adjudication: the exact public file remains inadmissible as a new confirmatory LAVA input.** The original-paper overall-N proxy plus strong BOLT release-class evidence justify sensitivity/diagnostic use, not promotion under the already locked rules. A stronger file-specific BOLT export statement alone would still leave the N and LAVA model-mapping requirements to satisfy. Relaxing those requirements after seeing results would require a new prospective protocol, not an edit to v1.

As an independent feasibility result, the prespecified [88-locus terminal decision](../../lava_confirmatory_pilots_v1/longsleep_linear_88_terminal_20260927.md) reported 44/88 `TESTED` in the primary linear arm versus 44/88 canonical (zero net gain; below the ≥9-locus threshold), and 47/88 in the binary sensitivity. That outcome gives **no justification for a larger original-source screen** under the addendum. It did not select the analysis class or resolve source admission. The binary sensitivity cannot replace the primary because it tested three more loci. No full outcome or candidate association was inspected for this ledger extension.
