# Long-sleep linear-model LAVA pilot: pre-run addendum

**Scope: prospective trait-only diagnostic, no source or family admission.** This addendum is fixed before generating new long-sleep association-level LAVA outputs. It does not change `sample_size_and_overlap_protocol.md`, the canonical 17,465-cell family, its 5% maximum untested threshold, the five pairs, or candidate promotion. It addresses the original Dashti 2019 `>=9 h` versus `7–8 h` source, not a new phenotype.

## Source and method basis

- The original archive is `/Volumes/Extreme SSD/brain6-work/atlas-raw/.archives/longsumstats.txt.zip`, SHA-256 `0afd9a3ccf459d283f1b6eb6a8b8b0780f54d9d634a05f816be31171a42ec885`; its [release README](../lava_confirmatory_source_triage_v1/source_docs/Saxena_fullUKBB_Longsleep_summary_stats_README) is SHA-256 `ec79d6599ad8ec0353c2d8476bd182e512b5a333519c5b6d9263bf2a9e9df0aa`. Dashti et al. report 34,184 cases and 305,742 controls, total `N=339,926`, from European-ancestry UK Biobank. The primary paper's BOLT-LMM methods and a [coauthored follow-up](https://www.nature.com/articles/s41467-019-11456-7) identify the public long-sleep genome-wide release as BOLT-LMM, not the separate PLINK logistic odds-ratio check.
- The [official BOLT-LMM manual](https://storage.googleapis.com/broad-alkesgroup-public/BOLT-LMM/BOLT-LMM_manual.html) says case-control phenotypes are treated as quantitative and analyzed with a linear model. The original release has `BETA`, `SE`, and `P` but no per-variant `N`. Source-only checks of 1,000 and 70,150 high-quality variants support a highly stable linear SE scale; the [genome-wide receipt](../lava_confirmatory_source_triage_v1/longsleep_se_stability_v1.json), SHA-256 `602196c143fea81a696e656fd9f500c33db1060b443593fa239c40de32e7c49f`, scanned 14,661,601 rows without using beta or association P. These facts justify examining published total `N` as a **diagnostic proxy** in high-quality variants. They do not prove exact per-variant analyzed `N`.
- The [pinned LAVA 0.1.5 source](https://github.com/josefin-werme/LAVA/tree/e729a245f7b6923967a96804fbf5246eadf2d6c6) converts a linear-model `Z` to a SNP correlation using `Z/sqrt(Z²+N-2)` and uses an F test. Its binary path reconstructs marginal logistic statistics from `Z`, `N`, reference frequency, and case fraction, then uses a chi-square univariate test. The [LAVA methods paper](https://research.vu.nl/ws/files/155730906/An_integrated_framework_for_local_genetic_correlation_analysis.pdf) permits overall `N` as a proxy when per-SNP `N` is missing for the continuous model. It does not explicitly validate treating a BOLT-LMM binary-response scan as a continuous LAVA phenotype. This is the central model-compatibility uncertainty the pilot will expose, not resolve by whichever arm has more testable loci.

## Frozen diagnostic design

1. Select exactly **88** loci: the two smallest SHA-256 ranks in each of the frozen canonical long-sleep `TESTED` and `NOT_RUN` strata on each of 22 autosomes, using `brain6-longsleep-linear-pilot-v1|CHR|STATUS|LOC` as the rank string. Exclude every LAVA locus overlapping any of the 25 existing pair-specific PLACO candidate intervals before ranking. Use only locus coordinates and canonical status, never local P, effect, gene, or candidate association result. Save the selection and source hashes before running LAVA.
2. Use the sealed GRCh37 UK Biobank LAVA 1.1 reference, the original Dashti Z and effect alleles already aligned in the receipt-verified canonical long-sleep shards, and the same frozen LAVA locus-processing parameters. Independently verify each selected shard hash against its original materialization provenance. Only retain SNPs with unambiguous unique original source IDs, matching original source position/alleles, source INFO `>=0.95`, and source MAF `>=0.01`; quarantine discordance and duplicates. Preserve source Z, SNP and alleles byte-for-byte except filtering; set a new `N=339926` column in versioned SSD inputs. The 0.95 INFO filter is fixed from the source-only SE stability audit before pilot outcomes.
3. **Primary diagnostic arm, model aligned:** in LAVA input-info set `cases=NA`, `controls=NA`, because BOLT analyzed a linear 0/1 response. This invokes LAVA's linear Z-to-correlation and F-test path. **Secondary sensitivity arm:** use the exact same SNPs, Z and `N=339926`, with `cases=34184`, `controls=305742`, invoking LAVA's binary reconstruction. Both arms are fixed now; no arm may be selected by improved testability, significance or candidate-region outcome. The immutable canonical arm (`N=122985.408918...` and observed case fraction) is a historical comparator only.
4. Run four independent workers per arm with BLAS/OpenMP threads pinned to one. Keep arm outputs, configurations, input hashes, worker exits, and terminal receipts in separate versioned SSD directories. Audit all 88 selected loci per arm, old-versus-new status, shared-reference SNPs, numeric errors, local h² and strict-gate calls. Do not run any bivariate LAVA in this diagnostic.
   A selected locus with zero retained source-verified SNPs remains in both arm denominators as `NOT_RUN/NO_SOURCE_VERIFIED_SNPS`; it must not be silently dropped or replaced.
5. Interpret technical feasibility without choosing an input convention by outcome. A primary-arm gain of at least 10 percentage points in `TESTED` fraction over the same 88 canonical loci, zero numerical failures, and retention of at least 80% of each original canonical shard's SNPs in at least 90% of the selected loci is the *minimum* to justify considering a larger trait-only feasibility screen. A smaller gain or lower coverage ends this original-source repair route unless new source/method evidence appears. Even a gain does not admit long sleep to a full rescue: fixed-N approximation, binary-response linear-model calibration, genome-wide eligibility, and source-matched pair overlap remain open. Do not extrapolate an 88-locus sample to a 2,495-locus PASS without uncertainty.

No LAVA outcome was used to define these arms, filtering rules, selected-locus ranking, or advance criterion. The original v3 family remains `FAILED_QC_NOT_PROMOTED` regardless of this pilot.
