# MDD2025 balanced-equivalent LAVA sensitivity pilot: pre-run addendum

This addendum is fixed **before** running a new MDD2025 pilot arm. It supplements `sample_size_and_overlap_protocol.md`; it does not revise that document, the earlier 111-locus pilot, the canonical LAVA v3 family, or any gate.

## Source and method basis

The PGC MDD2025 no-23andMe European file is SHA-256 `5d6fc5aee638e73457da703b75e0b4d4dacfb1b87578fd464b771209c0dfb22a`. It provides per-variant `NEFF`, `NCAS`, and `NCON`. Its source metadata defines `NEFF` as a sum of effective sample sizes across contributing cohorts, while the [PGC paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC11829167/) defines the balanced case-control effective-size interpretation. The previous 111-locus pilot paired `NEFF` with the study-wide observed case fraction from 412,305 cases and 1,588,397 controls. That pilot produced 108/111 numeric `TESTED`, but the pairing was placed on scientific hold before promotion.

In a balanced-equivalent case-control cohort with `N = NEFF`, set modeled cases and controls to `NEFF/2` each. For a source cohort with `c` cases and `k` controls, `NEFF = 4ck/(c+k)` gives the same first-order case-control information as an equal-size balanced study. The [pinned LAVA binary source](source_docs/LAVA_binary_processing_e729a245.R) sets modeled cases to per-SNP `N * case.prop`, so its `input_info.tsv` can express the balanced model with `cases=1, controls=1` while the source's per-variant `NEFF` remains in each sumstats `N` column. These `1` values encode only a 0.5 fraction and are **not** actual PGC participant counts; actual source counts remain separately recorded. A [peer-reviewed applied LAVA analysis](https://doi.org/10.1016/j.neurobiolaging.2023.03.004) reports the same effective-N / half-effective-N case-control convention. This is a method-supported approximation for a heterogeneous meta-analysis, not proof that every contributing cohort or SNP behaves like a literal balanced cohort.

## Fixed pilot comparison

- Reuse the exact 111 loci, four worker partitions, source Z/NEFF shards, UKB LD reference, numeric settings, and strict univariate threshold from `brain6/config/lava_multitrait_feasibility_v1/mdd2025_trait_pilot_v1.json`. The source shard bytes and original input-info bytes must be verified against the prior materialization receipt before use. The new pilot writes to a separate `mdd2025_balanced_equivalent_pilot_v1` root on the SSD.
- Change **only** the model fraction: each new input-info row records the same trait/file and `cases=1`, `controls=1`. Every new file, worker configuration, result, and exit event receives its own SHA-256 receipt. Existing outputs remain read-only.
- Report TESTED/NOT_RUN/FAILED counts, local-h² and strict-gate agreement with the prior pilot at the same 111 loci, and the exact discordant loci. The new arm is a source-model sensitivity analysis. **Do not select an input model by larger testability, stronger association, or candidate-region outcomes.** A result that differs materially from the prior arm demonstrates model dependence and requires explicit uncertainty in any further source decision.
- No full MDD screen or seven-trait rescue follows from this pilot alone. MDD-only perfect repair would leave 3,131 canonical `NOT_RUN`, above 873. Changed-source pairwise LAVA additionally requires new source-matched overlap matrices and a defensible four-trait family strategy.
