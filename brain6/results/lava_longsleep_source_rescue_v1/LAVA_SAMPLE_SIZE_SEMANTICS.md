# LAVA 0.1.5 sample-size semantics for the exact long-sleep source

This is a source-code audit, not a change to the frozen LAVA family. Brain6 ran R 4.3.3 with LAVA 0.1.5 from `/Volumes/Extreme SSD/brain6-work/r-env-4.3.3-short/lib/R/library/LAVA`. The loaded package's deparsed `process.input`, `get.input.info`, `read.sumstats.file`, `process.locus`, `process.binary`, and `find.beta` functions each matched the corresponding frozen source snapshot byte-for-byte at the R-function level (`identical(deparse(...), deparse(...)) == TRUE`). The snapshots are from upstream commit [`e729a245f7b6923967a96804fbf5246eadf2d6c6`](https://github.com/josefin-werme/LAVA/tree/e729a245f7b6923967a96804fbf5246eadf2d6c6). Current [upstream README](https://github.com/josefin-werme/LAVA/blob/main/README.md) still identifies version 0.1.5 and specifies summary-statistic `N` as **number of samples**; its current [input](https://github.com/josefin-werme/LAVA/blob/main/R/input_processing.R), [binary](https://github.com/josefin-werme/LAVA/blob/main/R/binary_processing.R), and [univariate](https://github.com/josefin-werme/LAVA/blob/main/R/analysis_functions.R) code retains the relevant operations below. This comparison establishes relevant code behavior, not identity of every upstream file or commit.

## Data flow and equations

1. `read.sumstats.file` requires a summary-statistic `N`, `NMISS`, or `N_analyzed` field unless an explicit programmatic `N.override` is passed; it converts BETA+P or another supported signed statistic to a signed Z and retains SNP, alleles, STAT, and `N`. There is no default from the input-info table. [Frozen source lines 347–392](../lava_confirmatory_protocol_v1/source_docs/LAVA_input_processing_e729a245.R); [upstream lines around `read.sumstats.file`](https://github.com/josefin-werme/LAVA/blob/main/R/input_processing.R).
2. `get.input.info` computes `input$info$N = cases + controls`, `prop_cases = cases / N`, and `binary` from the fraction. The derived input-info `N` does **not** replace summary-statistic `N` in analysis; the README explicitly states this. Setting cases/controls to `NA` selects the continuous path. [Frozen source lines 448–465](../lava_confirmatory_protocol_v1/source_docs/LAVA_input_processing_e729a245.R); [README, Process input](../lava_confirmatory_protocol_v1/source_docs/LAVA_README_e729a245.md).
3. For a binary trait, `process.locus` sends each SNP's Z, its summary-statistic `N_i`, LD-reference frequency, and trait-wide `prop_cases` to `process.binary`. That routine computes `N.case_i = N_i * prop_cases` and genotype counts proportional to `N_i` and frequency, then finds logistic-regression coefficients whose Wald statistic matches the supplied Z and converts their expected genotype/outcome covariance into a SNP correlation. It does **not** internally convert a real total N to balanced-equivalent N. [Frozen input lines 88–103](../lava_confirmatory_protocol_v1/source_docs/LAVA_input_processing_e729a245.R); [frozen binary lines 3–27, 78–87](../lava_confirmatory_protocol_v1/source_docs/LAVA_binary_processing_e729a245.R).
4. For the continuous path, `process.locus` directly uses `r_i = Z_i / sqrt(Z_i² + N_i - 2)`; it never uses case fraction. In either path it uses mean locus `N` (with fallback and missing-N imputation) to cap retained LD PCs at `floor(max.prop.K * min(N))`, compute sampling variance `(1 - delta²)/(N - K - 1)`, observed local h², and suppress h² when `K/N > 0.1`. Thus a larger constant `N` can change local h² testability even with identical Z and SNPs. [Frozen input lines 88–103, 123–163](../lava_confirmatory_protocol_v1/source_docs/LAVA_input_processing_e729a245.R).
5. The installed `univariate.test` uses a chi-square survival probability for binary traits and an F survival probability with denominator degrees of freedom `N - K - 1` for the continuous path. [Current upstream `analysis_functions.R`, `univariate.test`](https://github.com/josefin-werme/LAVA/blob/main/R/analysis_functions.R). The installed R namespace was inspected directly on 2026-09-27.

## Consequence for Dashti long sleep

The exact source has 34,184 cases, 305,742 controls, total 339,926, and observed fraction `0.10056306372563441`. The original archive has no N or case/control columns. The historical Brain6 [harmonizer lines 638–665](../../../scripts/01_harmonize.py) mapped the binary trait's configuration counts into a constant `N_eff = 4*34184*305742/339926 = 122985.40891841166`. Its [QC receipt](</Volumes/Extreme SSD/Utsav-Research-Archive/Sleep-GWAS/Sep1-local-dependencies/data/harmonized/longsleep.qc.txt>) says `CONSTANT_N_EFF_FROM_MANIFEST`; the verified harmonized file's first row has `N=122985.40891841165`, while the native source has no N. [The LAVA input-info builder](../../../scripts/31_prepare_lava.py) separately passed the observed 34,184/305,742 counts. The [source card](../../../extensions/brain6/work/overnight-v03/source-cards/longsleep.source.json) then treated the already-munged `N` column as `n_semantics: total`, a historical label that does not make its numerical value a total N.

With the historical `N_eff` and observed fraction, LAVA's logistic reconstruction implicitly models **12,367.79 cases and 110,617.62 controls per SNP**, not 34,184 and 305,742. This is algebraically a scaled cohort with the same case fraction, not the original cohort. Using `N_eff` with a 50/50 fraction would imply 61,492.70 cases and controls: a different synthetic balanced cohort, with no source or LAVA validation for these BOLT statistics. Neither choice is authorized by higher testability.

Using total `N=339,926` with the observed fraction yields the **study-level counts** inside the binary reconstruction, but that is only count-coherent if every SNP has the same analyzed N and if its Z is an appropriate logistic/Wald input. The source does not report SNP-level N, the paper allows SNP missingness, and the public genome-wide effects are supported as BOLT-LMM linear-model rather than logistic effects. The prior blinded [88-locus diagnostic](../lava_confirmatory_pilots_v1/longsleep_linear_88_terminal_20260927.md) used `N=339,926` in both predeclared continuous and binary paths; the primary linear path gained **0/88** TESTED loci and did not satisfy its prospective advance criterion. No representation from that pilot gained full-source admission. A larger constant N must not be selected because it numerically changes h² calls.

**Current conclusion:** LAVA accepts literal per-SNP sample counts in its equations. The public source has no such field; total study N is not established as every SNP's N, and its BOLT-LMM Z has no demonstrated exact mapping into LAVA's logistic reconstruction. The historical `N_eff`/observed-fraction pairing is not source-faithful. These unresolved assumptions block a source-valid full-family input, regardless of whether individual loci become numerically TESTED.
