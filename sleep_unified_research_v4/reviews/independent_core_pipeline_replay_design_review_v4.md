## Source and baseline provenance

The current v3 ledger resolves 45/45 raw inputs against their historical expected SHA-256 values. This metadata-only review confirms those bindings and current file sizes, not a new body hash. The exact source-container count is now 42/43, with the original prostate container unresolved because the public candidate differs. Its exact original materialized raw is available. A raw-stage replay can therefore cover all 45; complete original-container-to-raw reproduction cannot be claimed for all 43 containers.

The original nine HM3 prefilters are LDL, HDL, triglycerides, MS, asthma, T2D, CAD, telomere length and melanoma. LDL/HDL/triglycerides already have successful independent/native v2 prefilter receipts with identical original compressed SHA and source/retained counts; the design reuses those outputs and their provenance as read-only inputs. The six remaining prefilters requiring replay are **MS, asthma, T2D, CAD, telomere length and melanoma**. The original prefilter performs literal lowercase whole-field rsID allowlist matching, copies selected physical rows verbatim in source order and writes deterministic gzip. It does not expand multi-ID fields into new matches. That behavior must be preserved.

Nine prefilter hashes have historical expected hashes recorded by archived QC. The 45 harmonized and 45 munged hashes are sealed v1 audit-time recorded hashes with status `HASH_RECORDED_NO_HISTORICAL_EXPECTED_HASH`. They are valid available comparison baselines, but they are not historical expected checkpoint hashes. The manifest keeps this distinction rather than promoting them to checkpoint identities. Full decompressed baseline hashes have not yet been computed in this review.

Independent before/after hashing covered 122 small metadata, code, binary and reference files totaling 32,616,125 bytes with 64 KiB buffers and peak RSS 25,837,568 bytes. Archived QC arithmetic reconciles every trait's ordered drops, rows in and rows out. Munging logs agree with each harmonized row count and record 1,217,311 output skeleton rows per trait, with trait-specific nonmissing counts captured in the manifest. No source/statistic arrays or SNP-level rows were saved to Git.

## Method and runtime identity

Current `01_harmonize.py`, `21_prefilter_hm3.py`, `variant_map.py` and `liftover_chain.py` are byte-identical to original main commit `659d01cf5b10a6debf1841404e7e01ef4750f755`. The seven panel/schema/source/mapping/prefilter/lock config files are exactly identical across current files, that original Git snapshot and the archived config copies. Current `02_munge.sh` and `_common.sh` differ by output/reference directory routing and workspace/storage setup, with scientific argv and filtering unchanged. The shell still hardcodes `data/raw/$raw_file`, so the design gives explicit absolute-input Python commands rather than invoking the shell against historical directories. Pinned `munge_sumstats.py` matches CBIIT LDSC commit `6c673952cee74bd5c57aef1555a03b1c015399a0`; the prior v1 LDSC source comparison did not itself cover that separate munging file, so it was checked here.

This establishes current-versus-original source/config identity, not an independently proven per-trait historical code/runtime execution attestation. The original declared workflow pins are Python 3.11.11, numpy 1.26.4 and pandas 2.2.3. The recovered hash-bound native LDSC environment is Python 3.9.23, numpy 1.21.5, pandas 1.3.3 and scipy 1.7.3. These are distinct parser/serialization environments. The original harmonization executable has not been established by this review. Accordingly the original harmonizer command template deliberately uses `{FROZEN_HARMONIZATION_PYTHON}`; substituting native Python 3.9 without an explicit version qualification would not establish identical historical runtime reproduction.

The scientific implementation preserves alias priority and BETA over redundant OR; OR inputs become log(OR). One-based pinned liftover complements alleles on reverse strand without negating the source beta solely for strand change. Coordinate/rsID-and-allele mapping uses the exact 9,948,937-byte HM3 map and its provenance. Invalid variants, ambiguous alleles, source P, beta/SE, coordinates, INFO, frequency, MHC and duplicate rules are sequential and source-order-sensitive.

Preserve original INFO >0.6 behavior, including qualified missingness, and the original floating-point MAF expression. The known literal 0.99 arithmetic behavior must remain for historical core reproduction; the corrected new FinnGen source rule must not be silently transplanted here. Original INFO is omitted from the final harmonized schema, and 27 traits have archived INFO-absence qualification. Seven traits alone have FRQ-absence proof and stock `--ignore FRQ`: IBD, Crohn, UC, RA, atrial fibrillation, breast cancer and colorectal cancer. No INFO/frequency/sample-size fabrication or repair is authorized.

Sample-size branch priority and transformations remain exact, including 2×Effective_N/NEFFDIV2 and configured binary effective N. First duplicate removal occurs after earlier scientific filters but before the final sample-size gate. The N maximum/reference is global after that deduplication. A streaming implementation must not rescue a later high-N duplicate when the first surviving pre-N row fails the final cutoff. The original MS/melanoma effective-N coding remains unchanged; their separately proposed total-N sensitivities are not this replay.

Stock munging uses `--merge-alleles`, `--chunksize 500000`, its post-family global N 90th-percentile/1.5 cutoff, sign median checks and the complete HM3 left join. It computes signed Z from source P using `sqrt(chi2.isf(P,1))` and effect direction, rather than beta/SE. Its output rounds numeric fields to three decimals. Those scientific and serialization rules are necessary to reproduce the actual archived files.

## Memory and bounded alternative

`01_harmonize.py` still reads the whole selected source table with `pd.read_csv`; `low_memory=True` changes parser inference and does not supply a chunk iterator or a memory quota. It then builds string columns, mapping/liftover lists, global key sets, masks and copied filtered DataFrames. Thirty-five traits have at least five million harmonizer input rows, including the 20,170,208-row sleep-apnea source. These are conservatively flagged as likely to exceed a 2 GiB owned-worker bound; no measured peak is invented. The nine prefiltered inputs plus BMI are smaller, but their full-table peak also remains unmeasured.

A justified alternative is a distinct, prospectively reviewed streaming implementation with small source chunks and SSD spools/indexes. Its first pass must preserve parser/coercion decisions, exact scientific filter order, map/liftover behavior, source-order first duplicates and global N information. A disk-backed exact duplicate index avoids a multi-million-entry Python set. A second pass applies the original global N branch/cutoff and emits the original schema in source order. It must preserve global dtype and missingness/serialization behavior, not silently force new floating types. Do not add HM3 prefilters to traits whose original harmonized output retained genome-wide variants. Retain stock munging for the final approximately 1.2-million-SNP family.

The accompanying machine-readable rules specify required adversarial small controls before that new implementation is admitted: duplicate/chunk boundaries and first-low-N duplicates, global max/quantile behavior, missing/invalid N, INFO/FRQ absence versus missingness, P-zero/invalid behavior, OR/BETA priority, reverse mapping, ambiguity, MAF endpoints and parser/dtype cases. Synthetic tests cannot establish real source replay or biology. If exact historical runtime semantics cannot be restored, preserve and report that implementation qualification; do not relabel content failures as exact reproduction.

The historical final gzip baseline footprint is 4,775,938,704 bytes harmonized plus 402,446,089 bytes munged. This 5,178,384,793-byte total excludes new uncompressed spools, indexes, temporary files, logs and prefilters. A separate complete SSD resource reservation is required. Original helpers permit overwrites or replacement in some paths, so the future supervisor must reject all preexisting output/failed-attempt paths, bind a new namespace, hold the shared heavy-worker lock, enforce one worker/thread, track aggregate owned RSS, defer catchable signals, preserve failure journals and verify teardown and post-hash terminal gates.
