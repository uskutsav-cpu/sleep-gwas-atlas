## Decision

The proposed study addresses a defensible narrow question: whether an integrated source-linked lookup with contextual interpretation improves performance on twelve purposively selected interpretation tasks, when both workflows have the same numerical records and source evidence. Its status as an unrecruited feasibility pilot is correctly explicit. It cannot establish superiority over all existing genomic platforms, representative research-task performance or biological discovery.

**Prepare the packet for execution after the material issues below are resolved prospectively. It is not yet ready to collect responses.** Human institutional/source-use decisions and independent recruitment/scoring remain necessary. There is no scientific basis to report a measured human benefit before responses exist.

## Material issues to fix before collection

1. **Shared-record carryover is more specific than the protocol admits.** T04 and T05 both ask about the same external insomnia–abdominal-pain record. In P01–P10 they are assigned to opposite workflows; P11–P12 keep them together. A participant can retain the record, accession and context from the first task and reuse them in the second workflow. The protocol sentence that different tasks prevent same-question carryover is therefore too strong. The safer finite fix is to allocate shared-record task groups together and balance groups across participants, or select distinct compatible records before responses. Retain the original packet and document any replacement. Random ordering alone does not remove learning; remaining shared-construct learning must still be reported.

2. **Define the denominator and failure states prospectively.** “Fully supported / assessable tasks” does not specify whether incomplete answers, timeouts, tool-access failures and refusals are assessable failures or omitted. If a workflow produces fewer completed answers, excluding its incompletes can inflate conditional correctness. A simple pilot solution is fully supported / all six assigned tasks as the principal completion-and-correctness summary, with correctness among completed/assessable answers separately reported. Alternatively, define every exclusion in advance and report both estimands. Freeze task time limits or the absence of limits, timing start/stop rules, and handling of interruptions. Keep task/participant missingness visible. No participant-level inference can use task answers as independent people.

3. **The current scoring key undercovers some prompts and lacks numerical tolerances.** T12 asks which fields are absent or UNKNOWN, but its key explicitly requires only phenotype_type=UNKNOWN. The inspected catalog also has empty build, sample_size, cases, controls, PMID and DOI; its note says counts/build/rights were not established in the frozen crosswalk. The key must require the fields the prompt asks for, or narrow the prompt. T11 asks distinct measurement identities, but naming only “duration, efficiency, timing” is insufficient: require summed detected sleep episodes within the main sleep period, detected-sleep/main-period-length efficiency, and midpoint of main-period boundaries, plus the distinct trait IDs. T04 asks sources for discovery and validation: explicitly include the discovery outcome source PANUKBB_2025_RELEASE, alongside its exact trait ID. Define accepted paraphrases, rounded numerical answers and material unsupported claims before scoring. T07 illustrates the need: its baseline interval differs by about 8.4e-7 between the core and sensitivity exports because their critical-value precision differs; both describe the same marginal interval and should be accepted with a declared rounding rule. Literal full-precision string matching would be scientifically inappropriate. Source-supported clinical/causal/replication cautions should be marked consistently without requiring copied boilerplate.

4. **Finish the evidence freeze and reconcile the inventory.** The protocol says eight candidate TSVs, but shared_evidence_manifest.json inventories six TSVs plus SCHEMA.md. Those six are exactly the tabular files read by the current query, and cover the present tasks; the larger candidate release contains two further TSVs. State the intended participant-access set accurately and provide identical files in both workflows. The manifest currently freezes no primary document or URL version separately. Source URLs embedded in sleep_constructs.tsv provide equal links, but are not a frozen document set. Add the source documents or versioned access records actually needed, with identical access for both conditions; retain failed source access rather than selectively supplying intervention-only evidence. This matters because live field pages and newly recovered metadata can differ from the old frozen crosswalk. For T12, explicitly ask about the frozen candidate catalog, as the current prompt does; do not penalize a participant for distinguishing newer external metadata from the frozen table.

5. **Label the intervention correctly and keep the private key private.** query_atlas.py adds explicit interpretation text about marginal intervals, causality, independence and absent rows. The comparison measures integration plus contextual guardrails, not lookup convenience alone. These qualifications have supporting information in the shared release, so this need not violate evidence equality, but the claimed treatment should include contextualization. Task selection intentionally emphasizes those guardrails, limiting generalization. Distribute neither scoring_key_private.json nor this source-answer-bearing review to participants. Strip output-format identifiers where feasible before human scoring; simple removal of workflow labels cannot fully blind a scorer if answers reproduce distinctive query wording. Record residual unblinding as a limitation.
