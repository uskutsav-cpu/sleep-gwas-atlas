Condition A is scientifically different from B/C
A does not authenticate the exact target atlas source/release for any of the 60 final questions. Null target factual fields are therefore legitimate abstentions, not missing-data errors or zero estimates. Conservative judgments that evidence does not establish genetic absence, supported independence, causal direction, intervention effects, novelty or a calibrated contrast are distinct from unavailable facts. The corrected gold makes that distinction explicit. The actual linked-record replication question can remain unknown when its exact records are unavailable, even while an unsupported independence claim is false.

A generic schema-aware safe-abstention policy matches56/60 final tasks and276/288 required fields without retrieving an atlas fact. This is an analytic baseline, not a model response or result. Resolved defects and scientific fixes
1. Initial A gold set every non-comparator field to null, including logical non-establishment judgments supported by supplied scope. The builder now has condition-specific false/NOT_ESTABLISHED judgments and explicit factual/admissibility field roles; the revised gold was checked independently.
2. Query prompts contained source IDs that could be read as factual evidence, although A expected unavailable IDs. The shared system now calls them unverified query selectors and requires an authenticated evidence row for factual source-ID retrieval.
3. FIN019 genome build used the literal UNRESOLVED despite an instruction to return null for unavailable facts. Missing metadata sentinels now normalize to null.
4. Availability wording conflicted with held-record gold, and the scorer initially treated AVAILABLE alone as unsafe inferential clearance. Status now has an explicit record-state mapping; held rows remain historical records. Wrong status is a correctness error. Only explicit requested hold-clearance claims trigger the unsafe-clearance indicator.
5. A proposed nine-session,60 tasks-per-session design would have introduced learning, source-answer carryover, context compaction and session/condition confounding. It was replaced before responses by fresh agents per cell for a bounded deterministic 10-item subset.
6. The scorer initially hardcoded60 tasks/180 cells per model and could emit source-weighted intervals for tiny subsets. It now reads the execution registration, distinguishes planned, observed, completed and unevaluable cells, reports actual A support/abstention metrics, and does not output a ten-item confidence interval. Five targeted scorer checks passed, including Boolean-versus-integer separation, nonfinite-number rejection, and the corrected unsafe-clearance logic.

What the task design measures
The tasks provide an exact record key, and most ask to copy an existing estimate, construct, gate flag, source label or the first displayed sensitivity/conventional row. B has separate named tables, but generally only the already selected atlas row and associated metadata. Both B and C receive the same pre-resolved scope and hold notes. Many interpretation fields repeat universally conservative answers. Accordingly, strict all-fields correctness is a finite exact retrieval/admissibility measure with a strong formatting and instruction-following component. It is not a validated general scientific-interpretation measure or a realistic open-ended resource-discovery test.

The current wording appropriately narrows the intended claim. Future broader claims would need an independently designed natural-language challenge set, realistic multirow retrieval/distractors, explicit ambiguity/source identity decisions, and a validated user-relevant interpretation rubric. Those additions are future work and must not be silently introduced after these responses. The unchanged human pilot remains a separate study; this AI audit supplies no approval of its private scoring key or administration.

Registration and statistical plan
The independently recomputed minimum SHA256(20261012|feasibility|task_id) selects exactly one final item in each of ten strata. The current 90 unique cells equal 10 items x 3 conditions x 3 aliases. Each alias has 30 cells and each condition 30; the six condition permutations occur five times each. All 90 scheduled packet references match complete master input objects, their SHA256 values and byte counts. No truncation is acceptable; maximum full-packet size is recorded in the registration.

Registered aliases are gpt-6.1-sol,gpt-6-sol,gpt-6-luna, all OpenAI, requested reasoning medium, fresh fork_turns=none per cell. They are separate model variants, not independent providers or confirmed independent model families. Effective backend version, temperature and seed are unknown/uncontrollable. The agent environment does not technically disable filesystem/tool access. Instruction-only isolation is a disclosed limitation, and actual observable access traces must be preserved. A solver declaration alone cannot prove blinding.

Primary feasibility reporting should give strict task correctness and paired C-minus-B differences on the ten selected items, separately per alias, with completion/schema/numeric/safety diagnostics. Ten items provide one observation per stratum, so report counts and denominators, not a general significance or interface-superiority claim. The eventual 60-item source-weighted Exp(1) interval is a dependence reweighting sensitivity with few source clusters, not provider-population uncertainty. Alias averaging does not create independent provider evidence. Missing cells must not be fabricated or silently counted as scientific failures, and incomplete pair subsets must be disclosed.
