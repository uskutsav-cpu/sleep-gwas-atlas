# LAVA chromosome 6 reference-ID failure overlap audit

Audit time: 2026-09-24 17:06 UTC. Read-only comparison of completed external receipts/logs, all 13 locked chromosome-6 summary inputs, the pinned reference index, and the harmonization QC records; no input, receipt, threshold, or collator rule was changed.

All 20 contiguous locus indices 950–969 are chromosome 6 loci with identical coordinates in `accel_sleep_duration` and `chronotype`. Both pairs have `PROCESS_FAILED` receipts at each index and the same error: `none of specified SNP IDs are present in reference data`. Thus the current chronotype prefix reproduces the full 20-locus failure block already present in the completed first pair. Chronotype logs in loci 950–955 additionally report 364,648 SNPs shared across datasets and 17 removed during allele alignment before the reference-ID error. The first pair also has its separate failure at locus 1484.

The cause is now established: all 20 loci (indices 950–969; chr6:25,684,630–33,864,262) lie within the pipeline’s pre-existing chr6:25–34 Mb MHC exclusion. The harmonization code defines this interval at `scripts/01_harmonize.py` and removes it before LAVA inputs are materialized. All 13 harmonized-source QC sidecars record nonzero removals for this exact exclusion (36,114–55,829 rows by trait). A read-only scan of every locked `chr06.sumstats.tsv.gz` found zero SNP IDs in the pinned UKB reference index for chr6:25–34 Mb; the `.info` reference index itself contains 46,488 SNP IDs in that interval (SHA-256 `4cb99759dbde57b4f9206f7c5e21ff8f38b0b87da2ab29b9dc91867b4fd29807`). Thus the LAVA worker reaches an empty locus/reference intersection because the analysis inputs intentionally exclude MHC, not because the reference lacks MHC coverage. The pinned LAVA source intersects reference-coordinate SNPs with the input SNPs before calling `read.ld`; when the intersection is empty, `read.ld` raises this exact message. Despite the now-understood cause, every failure remains classified as `PROCESS_FAILED` and counted under the frozen v1 worker/collator rule. No reclassification, threshold change, or exclusion was applied. The locked local-completeness limit is exceeded, so no local inference or PLACO input is justified.
