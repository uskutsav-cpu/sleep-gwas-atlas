# Research-only 15-marker scorer

**Reversal safeguard, 29 October 2026:** Reversed-allele dosages now fail by default. Prefer input dosages for the model's counted allele; use `--allow-verified-reversal` only after independently verifying every reversed row represents the same diploid biallelic contrast. This flag cannot inspect genotype records or verify the original GWAS coding. This changes previous command behavior and does not validate the score.

`score_15_research.py` calculates three separate raw additive sums from `unvalidated_15_variant_score_prototype.csv`: FI, inferred FFS and insomnia weights. These are postselected, unvalidated research quantities—not probabilities or predictions of an individual's disease or frailty. Do not combine the sums or infer clinical thresholds. Their source phenotype scales and allele conventions differ; the FFS direction and several multiallelic representations require further source verification.

The scorer takes a long-format CSV with columns `sample_id,variant,dosage_allele,other_allele,dosage`. For every sample, supply exactly one row per model variant, using verified biallelic diploid dosages on the same build and strand as the model. The dosage is the expected copy count of the stated dosage allele, between 0 and 2. For an explicitly reversed allele pair the scorer uses `2 - dosage`; this is valid only for a verified biallelic diploid contrast, and rsID plus two allele letters cannot establish that condition at a multiallelic site. The assumed build is GRCh37, not authenticated by this script. Users must independently establish build, reference allele, strand, imputation quality and ploidy before calculating scores. There is no automatic liftover, imputation, missing-value handling, sample QC or validation against phenotypes.

The script cannot detect a third allele from its two-label input. An A/T genotype at an A/G/T site has A dosage 1 but G dosage 0, so converting A to G as `2 − dosage` would wrongly yield 1. Matching input labels and passing numerical checks do not prove the biallelic assumption; resolve the source contrast and third-allele handling before scoring. [Shared-marker audit](score_15_22_shared_marker_crosswalk.md).

The [candidate-specific FFS alignment audit](score15_ffs_alignment_audit.csv) checks this file against the cached source-row lookup: all 15 coordinate and allele-pair matches reproduce the stored FFS weights under the assumed A1 convention, with allele order reversed for 10. Five of those 10 have more than two alleles in the project's GRCh37 reference annotation. These are reference annotations, not evidence that a third allele occurs in the source or future cohort; the actual source's variant coding and target data must be checked. Negating a coefficient for a reversed allele is justified only when the analyzed contrast and dosage representation support it. The [independent source-table consistency check](ffs_effect_allele_source_consistency_audit.md) supports A1 as the FFS effect allele at 37 published leads but does not settle multiallelic semantics at these candidates. Reproduce the candidate file with `python3 work/audit_15_ffs_allele_swaps.py` from the project root. This check verifies arithmetic and stored-row consistency, not an author-confirmed variant representation or score validity.

Run `python3 score_15_research.py --dosages path/to/dosages.csv --output path/to/new_scores.csv` with this file, `score_22_research.py` (providing the shared CSV reader), and the 15-marker weights in the same directory. `--weights` can point to an alternative 15-marker file. The output must not already exist. Missing, duplicated, unknown, mismatched, nonfinite or out-of-range observations fail the run before output creation. Results are raw sums with no standardization or calibration.

An implementation-only check compares all 503 public reference genotypes against a separate matrix multiplication, including deliberately reversed alleles, and checks selected invalid inputs. It is documented in `score_15_reference_implementation_check.json`. It does not validate a phenotype association, confirm source allele semantics, measure performance, or authorize clinical use. Independent participant outcome validation remains outstanding.
