# ENCODE regulatory-element overlap for the Stage 5 queue

The UCSC Genome Browser's [ENCODE4 cCRE registry](https://genome.ucsc.edu/cgi-bin/hgTables?db=hg38&hgta_doSchema=describe+table+schema&hgta_group=regulation&hgta_table=cCREregistry&hgta_track=cCREregistry) was queried on 27 October 2026 for reference spans of all 488 GRCh38 queue variants. The 56 interval queries succeeded; 134 variants overlap a registry element. Coordinates in the detailed table use zero-based, half-open intervals. SNVs use their reference base; deletions use the full reference allele span; insertions use their anchor base, which is only an approximation of insertion-boundary overlap. The [per-variant table](stage5_encode_ccre_variant_overlap.csv), [element details](stage5_encode_ccre_overlap_detail.csv), [raw query responses](stage5_encode_ccre_query_responses.zip), and [audit](stage5_encode_ccre_overlap_receipt.json) preserve the evidence and exact public queries.

The FOXP2-region marker rs12536335 (chr7:114403104 A>G) overlaps the registry's distal-enhancer candidate EH38E3794718. The rs323509 marker, rs60271 alternative, FOXP2 insertion anchor, and SMAD5-region rs7734045 have no exact reference-span overlap in this registry. A non-overlap is not evidence that the variant has no regulatory effect, and an element overlap does not prove the alternate allele changes that element, link it to a particular gene, or establish a trait association.

The registry aggregates experimental chromatin and binding data across contexts; the query result does not identify the tissue responsible for the classification. Its assays may overlap the datasets used to train AlphaGenome, so the overlap is **not established independent validation**. Max Z scores in the detail file are aggregate element-level annotations, not variant-level differences or direct tests of the model's predicted direction. Follow-up requires cell-context-specific experimental evidence, matching the exact allele and molecular event, with training provenance checked.
