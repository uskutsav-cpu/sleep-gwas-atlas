# All of Us public browser: insomnia and muscle-weakness candidate lookup

> **Update, 29 October 2026:** The earlier specific-variant endpoint was significant-only. A later public Hail-backed regional query obtained full association rows for all 33 distinct project candidates in both outcomes. See the [new analysis](stage6_aou_full_candidate_association_review.md); the empty results described below were an endpoint limitation, not missing associations.

The [All by All browser](https://allbyall.researchallofus.org/) offers two potentially relevant CDR v8 phenotype analyses: binary PhecodeX **Insomnia (NS_333.2; 26,227 cases and 253,797 controls)** and **Muscle weakness (generalized) (SS_807.21; 7,521 cases and 275,944 controls)**, as displayed on 28 October 2026. The latter is a diagnosis/symptom code, not an FI, Fried frailty score, directly measured grip or knee strength, or a joint sleep–frailty phenotype. Full coding, sample overlap and target-population definitions require source-specific review.

We queried the public specific-variant association endpoint for the project's 22 count-prototype variants against both phenotypes, using the previously documented GRCh38 coordinate and allele pairs. **All 44 requests returned no row in this endpoint.** This is a statement about the selected public endpoint, not evidence that all variants were tested, have zero effect, are non-significant, or fail to replicate. No beta, SE or p-value was available for any of those requests, so no score-level statistic can be calculated from these responses. This is not a 44-test association result and cannot validate either score.

The browser's selected view of chr7-114403104-A-G (the project's rs12536335 mapping) displayed that variant's global annotation/count fields but blank p-value and beta for each selected phenotype. Those counts are not a phenotype association. Two positive controls from each phenotype's displayed Manhattan plot returned rows through the same endpoint: chr3-53494203-G-GA for insomnia (p=1.6446×10⁻⁹) and chr8-40846505-CT-C for generalized weakness (p=3.7291×10⁻⁹). They show the endpoint could return known selected rows, not that it had complete coverage of arbitrary variants.

At the browser build shown by the UI (`0.1.0-317fe0c-202609021906`), the [matching server source](https://github.com/broadinstitute/all-by-all-aou-browser/blob/317fe0c/axaou-server/src/variants/annotations.rs) says the variant-specific endpoint queries only its `significant_variants` table; its SQL also uses `LIMIT 1` without applying the declared ancestry and sequencing-type parameters. A returned row must therefore be inspected for its reported population and sequencing type, and absence must not be converted into a specific p-value. The [walkthrough](https://allbyall.researchallofus.org/walkthrough) describes browser views and the [All by All preprint](https://doi.org/10.64898/2026.05.08.26350964) describes the cohort and methods. Full outcome/genotype data require the separate controlled research environment, as described by [All of Us](https://allbyall.researchallofus.org/about).

Reproduce with `python3 outputs/stage6_aou_public_variant_screen.py`. The [table](stage6_aou_public_variant_screen.csv) records the requested pairs, mapping provenance and empty lookup status; the [receipt](stage6_aou_public_variant_screen.json) preserves the positive-control results, source versions and input hashes. Build mappings and allele representations were inherited from prior project work rather than independently revalidated here. Endpoint behavior and browser data can change. All of Us sample or close-relative non-overlap with discovery/selection has not been established. This public screen is a feasibility result, not individual validation or evidence of a negative association.
