# NCDS target-marker coverage request

The [candidate marker table](ncds_score_variant_request.csv) packages the 15-marker weighted prototype, 22-marker equal-weight count, and 22-marker weighted prototype for a future permitted coverage check. It is built entirely from existing project files and public UCSC genome-conversion chains; it does not contain participant data or demonstrate that any marker is present in NCDS.

The three files yield 59 list rows and 33 distinct rsIDs. Each row had exactly one GRCh37-to-GRCh38 coordinate mapping and exactly one reverse mapping back to the original coordinate, with no strand flips in this conversion. This checks coordinate transformation, not correct source-build assignment, allele identity, multiallelic representation, reference alleles, imputation, or target data quality. The 22-marker count and weighted lists can have different counted alleles; keep their rows separate. GRCh37 coordinates in the source files are inferred or assumed, so the GRCh38 positions are provisional. Do not use this table as a validated scoring file.

The CLS [NCDS documentation](https://cls-genetics.github.io/docs/NCDS.html) reports a GRCh38 TOPMed-imputed, QC-filtered PLINK-format release with 6,396 people and 7,545,708 variants; it describes filters including INFO below 0.8, MAF below 1% and more than two alleles. A separate HRC release is on GRCh37. Release counts alone do not prove any of the project variants survived; NCDS-specific MAF, per-array imputation quality and handling of multiallelic records require actual released data or authorized metadata. The representation and allele fields need verification, as does availability of dosage rather than only hard calls. A search of the public CLS genetics documentation and its 29-entry GitHub repository tree did not locate a retained-variant inventory; this was a bounded search, not proof no metadata exists elsewhere.

For each unique marker, an authorized assessor should check exact reference/alternate alleles and locus in the selected release, target rsID aliases, QC inclusion and variant-specific imputation quality, sample-level missingness and allele frequency. Then check the intersection of eligible genotypes with age-62 grip, gait, and age-50 and/or age-62 sleep and frailty variables; report the cohort and ancestry breakdown, disclosure-safe counts, and overlap with discovery/selection participants and their relatives. Ask whether survey fields can be supplied through the [direct CLS linked-data route](https://cls.ucl.ac.uk/data-access-training/data-access/accessing-data-directly-from-cls/); EGA's unlinked NCDS genetic release alone does not support this analysis. No communication or access request was sent.

Reproduce with `python3 work/ncds_score_variant_request.py` and installed `pyliftover`; the [receipt](ncds_score_variant_request.json) records input hashes and checks. The reference conversion chain files and individual score definitions remain separate from the target-dataset QC process.

An [additional reference audit](ncds_15_grch38_reference_audit.md) checked the 15-marker request against previously saved Ensembl GRCh38 mappings: 15 positions and allele listings match, with nine reference entries listing more than two alleles. This is not evidence of NCDS marker inclusion or of correct GWAS effect coding; the 22-marker list was not fully checked against that saved inventory.

A [22-marker GRCh38 screen](ncds_22_grch38_ensembl_review.md) found matches for 10 live Ensembl lookups, and two more using previously saved reference mappings; ten markers remain unverified after live-request failures. This is not target-cohort coverage.

A retry added reference support for rs34290943, bringing the combined reference check to 13/22; nine remain unverified. See the updated [screen](ncds_22_grch38_ensembl_review.md).
