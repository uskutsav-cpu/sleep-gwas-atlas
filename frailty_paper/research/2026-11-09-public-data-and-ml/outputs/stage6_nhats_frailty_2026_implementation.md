# NHATS 2026 physical-frailty implementation for genetic validation

Checked 29 October 2026. The NHATS team released [Technical Paper 58 and R, SAS and Stata programs](https://nhats.org/sites/default/files/public-documentation/NHATSTechnicalPaper58_01202026.zip). This is public documentation and code, not participant data. Its existence makes a prospective NHATS validation more reproducible, but does not grant access or establish sample overlap.

The paper specifies five components: low energy, low activity, weight loss/low BMI, slow gait and weak grip. Low energy requires low energy or exhaustion that limits activities, so it is related to fatigue even though it is not a direct insomnia question. Retain the standard published five-component phenotype as the primary outcome; an exhaustion-excluded four-component count is a **nonstandard sensitivity measure**, not a validated replacement Fried classification. Prespecify interpretation and thresholds and report its continuous count or prespecified categories without calling them the original three-level phenotype.

The authors' classification calculates a minimum count from observed positive components and a maximum count by treating missing components as potentially positive. It assigns definite robust (0), prefrail (1–2) or frail (3–5) only when the range supports that classification, and includes indefinite categories such as not-frail and indeterminate. A binary frail/not-frail analysis can include records unambiguously below three, but indeterminate cases cannot simply be coded non-frail. The documentation also flags non-applicable records and provides component-level variables. Do not replace the published definition with a count that silently treats all missing components as zero.

Round 7 is especially relevant because the genotype biospecimen was collected then; however, the genotype–frailty–sleep joint sample size is not publicly established by this documentation. Round 10 had no in-person walking and grip tests due to the pandemic, so it is a poor default for a full five-component analysis. Follow the source's unable/unsafe and missing-component rules; don't automatically equate no measured performance with a missing value. Before adopting any code, check versions and data encodings inside the approved environment.

One implementation question needs resolution before analysis: in the technical paper's low-activity missingness summary, the phrase “all questions missing” is followed by “either or both questions were not answered.” The bundled R code classifies both negative-coded responses as missing but otherwise defaults to non-low-activity after testing whether both are no. In particular, when one response is a negative missing code and the other is “no”, that code path appears to return 0 rather than missing. This is a reading of the public program; verify its input encodings, compare the SAS/Stata implementations and check with the authors if necessary before making a decision. Document any deviation and run a sensitivity analysis. The paper's gait-component variable description also appears to contain a copy-edit error referring to weight loss; use its criteria and actual implementation instead of the label alone.

The source archive has been retained as `work/nhats_frailty_technical58.zip`; extracted scripts and paper are in `work/nhats_frailty_technical58/`. No NHATS participant data were obtained or uploaded. Genetic access remains controlled, currently described as no access fee; eligibility, phenotype linkage, score-marker coverage, sample independence, and genetic-subset weights remain unverified. See the [validation feasibility review](stage6_nhats_genetic_validation_feasibility.md).

## Follow-up: synthetic cross-language rule audit

The R, SAS and Stata programs all use the same low-activity rule for the tested **numeric negative missing codes**: both answers “no” gives 1; both negative gives missing; any other combination gives 0. The [nine-case synthetic truth table](stage6_nhats_activity_synthetic_truth_table.csv), generated by [this R script](../work/nhats_activity_truth_table.R), verifies the published R expression on inputs 1 = yes, 2 = no and −1 = an illustrative negative missing code. Under a stricter information-based rule, the two combinations “no + missing” would be missing rather than not-low-activity. A reported “yes + missing” still suffices to classify not-low-activity. The scripts were inspected for the other two languages; SAS and Stata were not executed. Native software-missing values may behave differently and are not covered by this table.

This distinction can change a frailty label: with two positive and two negative other components, the official 0 gives an observed count of 2 (prefrail), while an unknown activity component permits 2–3 (not robust but uncertain frail versus not frail). This is a constructed example, not a prevalence or estimated impact in NHATS. Run the published rule as specified, and prespecify a matched-sample sensitivity that sets “no + missing” to missing and reapplies the min/max classification; report the number of changed records only within the approved data environment and subject to release review. Whether this occurs and affects real records is unknown.
