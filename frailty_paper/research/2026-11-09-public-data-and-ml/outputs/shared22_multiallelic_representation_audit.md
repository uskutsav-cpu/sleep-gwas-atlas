# Allele-representation check for the 22-marker count

Fourteen of the 22 candidate rsIDs have more than two alleles listed in the project's broader Ensembl GRCh37 reference lookup. The [complete audit](shared22_multiallelic_representation_audit.csv) lists each score's counted allele, comparison allele, reference allele strings and additional listed alleles. This does **not** mean that the additional alleles occur in a particular dataset, that the original GWAS used a multiallelic model, or that any score value is wrong.

Each candidate also had one MVP and one HFRS row matching its mapped position and allele pair in the earlier screen. That is useful string-level evidence but does not prove that a future target dataset has the same genotype coding, ploidy, reference assembly or source-specific multiallelic representation. Matching an rsID and two allele strings alone cannot establish the conditions needed to reverse a dosage.

## Why the distinction matters

Consider rs28528997, whose score counts A against G; its broader reference lists A/G/T. In a **hypothetical** diploid G/T genotype, the G dosage is 1 but the A dosage is 0. Treating G as the only alternative and computing `2 − G dosage` would give an incorrect A dosage of 1. The hypothetical example does not establish that a G/T genotype is present in any project sample.

The scoring implementation accepts a preprocessed dosage table and rejects reversed-allele inputs by default. The optional `--allow-verified-reversal` flag permits `2 − dosage` only when the analyst has independently verified the required diploid biallelic contrast. The script cannot inspect a target VCF or prove those conditions. Before using a reversed dosage, the analyst must verify that this complement operation is valid for the exact record and sample, including ploidy, build, strand, normalization and any other alleles. If those conditions cannot be established, do not calculate that sample's score using this tool. Do not silently discard extra-allele carriers, substitute zero, or assume matching rsIDs resolve the ambiguity. Source-specific missingness and any exclusions require a prespecified policy and reporting.

This check concerns **score construction**, not whether a marker causes insomnia or frailty. The source associations remain post-selected and the 22-marker count has no outcome validation or clinical calibration. See the [score guide](shared22_score_research_guide.md), [scoring input documentation](score_22_research_readme.md) and [original source matching](song124_mvp_hfrs_followup.md).

## Cross-build reference comparison

For the nine markers previously unresolved by the GRCh38 Ensembl lookup, the later [UCSC dbSNP 155 check](ncds_ucsc_dbsnp155_review.json) listed exactly the same allele sets as this earlier GRCh37 Ensembl inventory. Six of the nine have three or four reference alleles. Agreement strengthens this reference annotation; it does not establish that a third allele occurs in the GWAS or target cohort, that a normalized multi-allelic variant is represented as a compatible biallelic contrast, or that the GWAS effect applies to an isolated alternate allele.

For a diploid multiallelic site with counted allele C, other listed score allele O, and combined dosage T for all additional alleles, copy counts satisfy C + O + T = 2. Consequently, replacing C by `2 - O` overstates C by exactly T. For the equal-weight count, reversing such a dosage therefore overstates the contribution by T; for a weighted sum, the signed contribution error is the score weight multiplied by T. This is an algebraic check, not an estimate of error in any cohort. If extra-allele dosage or the source effect contrast is unavailable, reference annotation alone cannot resolve the score.

## Reproducibility

The CSV was generated by joining the [count definition](unvalidated_22_shared_direction_score.csv) with the earlier [124-marker screen](song124_mvp_hfrs_joint_screen.csv) by rsID, checking that both score alleles occur in the recorded Ensembl allele list and that each of the 22 has one pair-matched row in each follow-up source. These checks inherit the original assumed GRCh37-to-GRCh38 mapping and do not independently validate the source's genotype model. No target genotypes or outcomes were analyzed.
