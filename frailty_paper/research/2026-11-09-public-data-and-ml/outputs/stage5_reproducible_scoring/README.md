# Stage 5 AlphaGenome scoring bundle

This bundle preserves the 488-row GRCh38 score queue, input-check receipts, and a portable version of the official AlphaGenome client runner. This bundle was used for the live run; see the separate live analysis and coverage audit for results and remaining limitations. `validation_only.json` records a local check of 488 unique inputs, exact key/column agreement, reference-interval construction and availability of the requested scorers with `alphagenome==0.10.0`. The stored reference and indel receipts describe checks performed earlier; the local check does not independently download or revalidate the reference genome.

From this directory, in an isolated Python environment, install the official package (`python -m pip install 'alphagenome==0.10.0'`) and check `python run_alphagenome.py --validate-only`. Supply an authorized API key through the `ALPHAGENOME_API_KEY` environment variable without committing it or putting it in a shared shell history. The code never writes the key to the output. Run a single-variant pilot using `python run_alphagenome.py --limit 1 --store pilot_scores`, inspect its score file, metadata, receipt, and actual returned modalities and contexts, then run `python run_alphagenome.py --store complete_scores` after confirming suitability and quota. The API and its terms determine access and usage limits. Plan storage separately; full files can be large.

The runner requests the official recommended RNA_SEQ, SPLICE_SITES, SPLICE_SITE_USAGE, SPLICE_JUNCTIONS, ATAC, DNASE, CHIP_HISTONE, CHIP_TF, CAGE, and PROCAP scorers with 1 Mb input and ALL_FOLDS. It writes per-variant compressed tables, input-hash and configuration receipts, returned scorer/output-type lists, and track metadata. A per-variant `complete` receipt means a nonempty API response was recorded and hashed; **it is not proof that every scorer, gene or requested tissue was present**. Inspect scorer and tissue coverage before integration, validate allele/coordinate/gene/tissue/event and effect-scale alignment against measured QTL, and document absent contexts. A result is skipped on resume only when its receipt, content hash and model configuration match. Failed variants are not counted as complete.

A live API pilot and 488-allele run have now been performed using this runner. The pilot demonstrated live response compatibility, while the coverage audit and tissue analysis describe missing outputs and remaining interpretation limits. The 28 indels and all 460 SNVs are in the queue, but the live scoring run has returned model outputs, with some modalities absent for some variants. QTL and independent functional validation are subsequent required steps. Do not interpret general AVI scores as phenotype risk or causal proof. Official documentation: https://google-deepmind-alphagenome.readthedocs-hosted.com/variant_scoring.html

A local simulated-response check passed for writing and hashing a synthetic result, skipping a matching result on resume, and failing an empty response. See `mock_check_receipt.json`. It mocked the model and tidy conversion, so it cannot establish compatibility with a live response.

After a live run, `python audit_scores.py --store complete_scores --output score_coverage_audit.csv` checks each queued allele's receipt, file hash, row count, configuration, variant identifier and output-type labels, and records the returned scorer descriptions. Run the audit on the live result directory to see current verified coverage. Output-type coverage does not verify exact scorer settings or track completeness. Variant-ID expectations have only been checked against client documentation and synthetic records; check them against the pilot's actual response. This audit does not evaluate tissue, gene, splice-event, genomic-coordinate or effect-direction compatibility; those require inspection and a separate biological comparison. In particular, the recommended splice-site, splice-site-usage and splice-junction scores are maximum absolute differences, so their signs cannot generally establish directional agreement with an sQTL beta. A shared gene or splice locus alone also does not establish colocalization. See the [official scoring definitions](https://google-deepmind-alphagenome.readthedocs-hosted.com/variant_scoring.html).

Compatibility check: in installed alphagenome 0.10.0, `tidy_scores` sets `output_type` to the requested output name but `variant_scorer` to a descriptive scorer string (for example, `GeneMaskLFCScorer(requested_output=RNA_SEQ)`). The audit uses output types, not scorer strings, for basic coverage. A local synthetic AnnData processed by the real client tidier verified this distinction, variant serialization, one missing modality and hash-tampering detection. It was not a live API response; assess the actual pilot before scaling up.

The runner checks that all returned variant identifiers match the requested allele before recording completion, and records any missing output types in the receipt. A local simulated wrong-variant response was rejected; only a live pilot can establish actual API compatibility. A nonempty response can still lack tracks, genes or output types and must not be treated as full coverage.
