# Public UK Personal Genome Project: score-validation feasibility

A separate [PGP-UK open-data resource](https://www.personalgenomes.org.uk/data/) is worth distinguishing from the previously inspected Harvard PGP snapshot. On 28 October 2026, its [public participant metadata API](https://www.personalgenomes.org.uk/api/v1.3/all_participants) returned **118 participant records**; 100 contained nonempty sequence-variation metadata labeled VCF, and 109 contained nonempty phenotype-questionnaire metadata. These are metadata counts, **not** counts of verified usable genotypes, linked outcomes, eligible participants or independent test subjects. No genome file was downloaded or score-variant coverage verified.

An aggregate-only keyword scan examined 2,367 questionnaire question/answer entries. It found no question labels matching the documented sleep/insomnia, frailty, grip-strength, walking/gait, fatigue or weight-loss patterns; an `eye colour` positive-control question appeared for 92 participants, indicating that the question field was inspected. The scan also checked answer text against these same limited patterns. See the aggregate [receipt and exact patterns](stage6_pgpuk_open_cohort_feasibility.json). We did not retain or present participant identifiers or individual answers. This is a narrow search of the returned `phenotype` questionnaire field, not an exhaustive analysis of profiles, clinical files, data outside the API, synonyms, age eligibility or actual phenotype definitions. Lack of a keyword hit does not establish that a participant is free of insomnia or frailty or that no relevant data exist elsewhere.

The metadata scan does **not** establish an adequate public sample with both genotypes and insomnia and a measured FI or FFS. At the displayed scale, even a much more complete phenotype inventory would not by itself establish sufficient events for reliable calibration, discrimination and subgroup analyses. The [resource's paper](https://doi.org/10.1038/s41597-019-0205-4) describes an openly consented multi-omics pilot; the present API count need not equal the earlier pilot sample. Participant/relative overlap with discovery, actual file availability, build, exact scored alleles and case ascertainment remain unverified. This lead cannot currently validate either project score.

Run `python3 outputs/stage6_pgpuk_open_cohort_feasibility.py` for an aggregate-only repeat. The script fetches public metadata into memory and writes only counts, fixed search expressions, a source hash and limitations. Source contents and availability can change; the source hash records the response checked, not a provider checksum or proof of full population coverage.

## Follow-up: listed VCF files

On a further read of the current public API metadata, all 100 VCF-labelled records advertised a VCF and a tabix/TBI-labelled index on the ENA FTP host; 11 also listed a manifest. Metadata labels do not establish that the variants, index and build are usable for our score. For a bounded connectivity check, HTTPS HEAD requests to the first three records ordered by analysis accession each timed out after 10 seconds in this environment (`curl` exit 28, no HTTP status). A direct indexed-reader attempt also did not open the first two files before the check was interrupted. These observations are **environment-specific** and do not prove that the files are unavailable from other networks or that all 100 links fail. No genotype coverage or score was computed.

Reference assembly must be checked per file: the [PGP-UK reference-panel paper](https://www.nature.com/articles/s41597-019-0205-4) describes hg19/GRCh37, whereas a [separate preprint](https://www.medrxiv.org/content/10.1101/2024.08.01.24311329v1.full.pdf) describes an 89-genome PGP-UK dataset as GRCh38. This does not identify the build for each API record and build differences make direct coordinate matching unsafe. Linkage to measured FI/FFS, sleep outcomes, independence, usable allele contrasts and statistical power remain unverified. No individual-level files were retained.

## Alternate hosting

The [Cancer Genomics Cloud documentation](https://docs.cancergenomicscloud.org/docs/pgp-uk-data) describes an open PGP-UK pilot project containing 13 participants, including 11 whole-genome and two whole-exome samples, under CC0. It is a possible alternative location for a small technical test; the page says no special authorization status is required for those data. Current account, computational-cost, linkage, outcome and file-availability conditions were not independently verified, and this small pilot cannot provide a credible full score-validation study on its own. No cloud account or job was created.

A further bounded HTTPS HEAD test of one metadata-listed VCF through both `ftp.sra.ebi.ac.uk` and the alternative `ftp.ebi.ac.uk` host timed out here after eight seconds each. This is not proof that the files are absent, that alternate routing is generally supported, or that cloud access will work. Together with the missing phenotype evidence, it leaves the project's score-validation question open.
