# LASI-DAD public LD lookup: two chromosome 18 score markers

The public [LASI-DAD LD panel](https://github.com/zhengli09/LASI_DAD-LD-Reference-Panel) is a population reference, not an individual-level validation cohort. We searched the full downloaded chromosome 18 pair table for the project's two 15-marker candidates, rs1942262 and rs11152363. Project liftover records give provisional GRCh38 coordinates 18:55206086 and 18:55389957, respectively, each with the G/A contrast. Both corresponding `G:A` identifiers occur elsewhere in the table (76 and 95 pair rows, respectively), supporting coverage of those exact coordinate–allele representations in this lookup. The table's displayed A-allele frequencies for those records are 0.2075 and 0.1527; they are reference-panel estimates, not frequencies in a verified score-validation sample.

The pair itself was **not found** in the full lookup. The source describes reporting variant pairs within 1 Mb only when haplotype r² is at least 0.2. These positions are 183,871 bases apart. Conditional on complete coverage and the stated filtering convention, the missing pair is consistent with r² below 0.2; its exact value is unknown. An omitted or malformed source record cannot be ruled out, and the table does not supply genotype correlation or an outcome association. This is not evidence that the variants are independent, causal, or predictive. The project coordinates are provisional and exact source variant identity, build and multiallelic handling remain subject to verification.

For context, an existing [1000 Genomes European lookup](selected_variant_pair_ld_reference.csv) reports r² 0.171 for this pair; this is a separate reference estimate with its own sampling and allele definitions. A missing thresholded LASI-DAD row cannot quantify a difference between populations. Neither lookup tests a score in people, and the LASI-DAD resource overlaps the potential future LASI-DAD validation cohort, so it is not an independent phenotype replication.

The downloaded table's SHA-256 is `f72c7e69696193d4369c36308c99bdf8f885ec919e5f157409a56e26fe5ed7df` (442,111,058 bytes). [Pair receipt](stage6_lasi_chr18_candidate_ld_receipt.json), [marker-presence receipt](stage6_lasi_chr18_marker_presence.json), and [code](../work/lasi/check_chr18_pair.py) / [presence code](../work/lasi/check_chr18_marker_presence.py) preserve the lookup. Both scripts scan the complete gzip; the pair scan uses the integer coordinates embedded in variant IDs because some numeric position fields use scientific notation. No user-level genotypes or sleep/frailty outcomes were accessed.
